# group_by

`source |> rx_group_by(key_selector[,max_groups])` разделяет значения одного
источника на горячие Observable по ключу. Значения не преобразуются: тип группы
содержит исходный T. Для отдельного преобразования используйте map внутри группы.

```dascript
var listeners:array<RxSubscription>
var inscope source <- rx_range(1,6) |> rx_group_by(@(n:int) {
    return n%2==0 ? "even" : "odd"
})
var inscope subscription <- rx_subscribe(source,
    @(group:typedecl(rx_group_marker(type<string>,type<int>))) {
        let key=rx_group_key(group)
        listeners |> emplace(rx_subscribe(group,
            @ capture(copy(key)) (n:int) {print("{key}: {n}\n")},
            @(message:string) {print("error: {message}\n")},
            @() {}))
    },@(message:string) {print("outer error: {message}\n")},@() {})
// odd: 1; even: 2; odd: 3; even: 4; odd: 5; even: 6.
// range выполняется синхронно; к этой строке все подписки завершены.
delete listeners
```

Полный исполняемый пример: [group_by_demo.das](examples/group_by_demo.das).

## Ключи и порядок

- Распознаватель вызывается один раз на принятое значение. Ключи должны быть
  copyable owning значениями с оператором `==`. Поддерживаются, например, int,
  string и собственные структуры с подходящим оператором сравнения.
- Строки сохраняются снимками; сравнение строк выполняется по содержимому.
  `rx_group_key(group)` возвращает копию ключа, которую можно сохранить.
- Внешний Observable выдаёт группу ровно один раз — при первом появлении ключа.
  Сначала выполняется внешний on_next(group), затем первый on_next(value) группы.
  Поэтому подписка внутри внешнего callback получает первый элемент.
- Порядок групп соответствует первому появлению ключей; порядок значений внутри
  группы соответствует источнику. Группы закрываются в порядке создания, затем
  приходит terminal внешнего потока. Для пустого источника групп нет.
- Повторная отправка в custom rx_create источник из распознавателя или callback
  сериализуется: уже обрабатываемое значение не может быть обогнано вложенным.

Состояние групп создаётся отдельно на каждую внешнюю подписку. Как и у остальных
операторов, захваченные изменяемые данные самой lambda key_selector принадлежат
дескриптору и разделяются повторными подписками. Для независимых captures нужен
rx_defer с построением цепочки внутри фабрики.

## Горячие группы и владение

Группа не хранит историю. Поздний подписчик получает только будущие значения;
подписка на завершённую группу сразу получает сохранённый terminal.
Отписка одного слушателя не удаляет ключ и не создаёт группу заново при следующем
значении. Отсутствие слушателей не завершает группу.

Внешний callback получает заимствованный дескриптор. Чтобы сохранить группу после
callback, используйте `rx_clone(group)`. `rx_group_marker(type<K>,type<T>)` — пустой
маркер для вывода типа сигнатуры; сам по себе он не создаёт группу или подписку.

Группы можно осматривать через map, а также пропускать через filter/tap/take и
другие не сохраняющие payload операторы. В flat_map группу передают явно клонированной:

```dascript
var inscope source <- rx_range(1,6) |> rx_group_by(@(n:int) {return n%2}) |> rx_filter(@(g:typedecl(rx_group_marker(type<int>,type<int>))) {return rx_group_key(g)==1}) |> rx_flat_map(@(g:typedecl(rx_group_marker(type<int>,type<int>))) {return <- rx_clone(g)})
// Подписчик source получит 1, 3, 5.
```

concat_map подписывается на группы последовательно: пока первая группа открыта,
горячие значения следующих групп могут быть пропущены. Передача самого дескриптора
группы в обычные сохраняющие payload операторы (share_replay, observe_on и т. п.)
не поддерживается общим контрактом Rx; преобразуйте его в обычные данные.

## Завершение, ошибки и отмена

| Причина | Группы | Внешняя подписка |
|---|---|---|
| Complete источника | Complete всех групп | Complete после групп |
| on_error источника | Та же ошибка всем группам | Та же ошибка после групп |
| Исключение key_selector или `==` | on_error всем группам | on_error после групп |
| Превышение max_groups | `rx_group_by: group limit exceeded` всем существующим группам | Та же ошибка; лишняя группа не объявляется |
| Отписка или удаление внешней подписки | Complete всех групп | Закрывается без terminal callback |
| Исключение observer callback/teardown | Закрытие всех групп и источника | Исключение распространяется вызывающему коду |

Группы следуют правилам уже существующего window: внешний unsubscribe немедленно
закрывает upstream и все группы, даже если у групп остались слушатели. Сохранённый
rx_clone удерживает только ключ и состояние завершённой группы; он не продлевает
жизнь исходного источника. Например, `group_by |> take(1)` прекращает исходную
подписку уже при объявлении первой группы, до доставки её первого значения.

При исключении в обработчике закрытия одной группы очистка остальных всё равно
выполняется. Такое исключение не превращается в on_error внешнего потока.
Callbacks и источник исполняются в одном потоке/контексте, как остальное ядро Rx.

## Ограничения хранения

max_groups по умолчанию 0 — без ограничения числа различных ключей. Положительное
значение задаёт предел реестра; отрицательное считается ошибкой настройки. Группы
остаются в реестре до закрытия внешней подписки, включая группы без слушателей.
Автоматического удаления по времени или отдельному сигналу в этом API нет.

Текущий поиск ключа линейный: O(G) сравнений на элемент, O(G) дескрипторов для G
различных ключей. Это позволяет использовать собственный `==` без отдельного hash
протокола. Для потенциально бесконечного пространства ключей задавайте max_groups.
Значения по-прежнему должны быть copyable owning; move-only payload не поддержан.
Очередь повторных входных событий сохраняет порядок, но не ограничена и не даёт
backpressure. В обычном синхронном обходе событие обрабатывается сразу.
