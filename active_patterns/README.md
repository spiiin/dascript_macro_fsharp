# Active patterns средствами стандартного match

Примеры используют обычные функции-распознаватели и стандартный макрос
`daslib/match`. Отдельный макрос или нативный модуль не нужен.
Нужен SDK **v0.6.5-RC2**, содержащий
[PR #4259](https://github.com/GaijinEntertainment/daScript/pull/4259).

Из корня репозитория:

```powershell
./active_patterns/run.ps1
./active_patterns/run.ps1 -Test
./active_patterns/run.ps1 -Test -Jit
```

Используйте `-Daslang <path>` или `DASLANG_EXE` для другого расположения SDK.
Официальный архив и SHA-256 закреплены в
[установщике CI](../.github/scripts/install-daslang.ps1).
Merge PR `34cb1e7def64418dd447c117671812692619cdf4` является предком
релиза `v0.6.5-RC2` (`82701dcd8ee48c2080009bdf2dce0121d057accb`).
Имя версии, которое печатает этот SDK, — `0.6.5`; RC2 обозначает конкретный релиз.

## Полное распознавание

`parity` возвращает enum. Обе ветки обязательны; неизвестного третьего исхода нет:

```das
let kind=match (parity(value)) {
    Parity.even => "even"
    Parity.odd => "odd"
}
```

Функция вызывается один раз. Для более сложной классификации вместо enum можно
вернуть variant с разными payload. Определения находятся в
[recognizers.das](recognizers.das).

## Частичное распознавание

`integer` возвращает variant `RecognizedInt`: `found` с числом либо `missing`.
Вызов внутри view pattern преобразует исходное значение, затем проверяет результат:

```das
let description=match (text) {
    (integer(_) => found(n)) && n < 0 => "negative {n}"
    (integer(_) => found(n)) => "integer {n}"
    _ => "text"
}
```

`_` внутри вызова означает текущий проверяемый объект. При `missing` ветка не
подходит. Можно возвращать стандартные Option/Result; тест показывает прямой
`(try_to_int(_) => ok(n))` без адаптера.

## Параметризованное распознавание

Дополнительные аргументы — обычные значения из области видимости:

```das
let eligibility=match (value) {
    (at_least(_,minimum) => found(level)) => "accepted {level}"
    _ => "too low"
}
```

Пример и тесты также сочетают views через `&` и вкладывают их в поля структуры.

## Границы

- Views требуют запасную `_` ветку: проверка полноты не доказывает поведение
  произвольной функции. Для полного классификатора используйте `match(f(value))`.
- View может вычисляться повторно при проверке веток. Распознаватели должны быть
  чистыми. Дорогое преобразование вычислите перед match или в его subject.
- Связанные значения являются read-only копиями по правилам стандартного match.
- F#-синтаксис `(|Name|_|)` и активные паттерны в параметрах функций здесь не
  вводятся. Это примеры аналогичной семантики, не новый DSL.

## Проверки

[test_active_patterns.das](tests/test_active_patterns.das) проверяет обе ветки
полного распознавателя, частичное распознавание и извлечение, отрицательные числа,
переполнение и посторонний текст, граничное значение параметра и его изменение,
вложенность, пересечение и стандартный Result. Отрицательные файлы проверяют
пропущенный случай enum, отсутствие fallback у полного view и частичного
распознавателя, несовместимый тип параметра. Runner проверяет ненулевой exit
и ожидаемый текст диагностики. CI запускает этот набор в интерпретаторе и JIT.
Генерация и исполнение AOT для этой новой папки не заявлены.
