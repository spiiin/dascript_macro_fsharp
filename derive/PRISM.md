# Prism: частичные пути через Option, JsonField и variant

Prism выбирает значение, только если все случаи variant на пути совпали.
Путь состоит из имён полей структур и имён случаев: `optional.some.health`,
`field.present.bonuses`, `action.stats.health`. Имена проверяются при компиляции;
runtime reflection и поиска поля по строке нет.

Пайповый пример, включая проверку пропуска callback:
[prism_demo.das](examples/prism_demo.das).

## API

| Выражение | Результат |
|---|---|
| `prism("optional.some.health")` | Постоянный дескриптор частичного пути |
| `prism("optional") \|> prism_then("some.health")` | Составной путь |
| `source \|> prism_try_get(path)` | `Option<Focus>` с независимым снимком либо `None` |
| `source \|> prism_matches(path)` | Совпали ли все случаи на пути; не клонирует заимствованный источник |
| `source \|> prism_set(path,replacement)` | Независимый корень; замена только при совпадении |
| `source \|> prism_over(path) <\| block` | Независимый корень; callback только при совпадении |

Корнем может быть структура, Option, JsonField или обычный variant.
На шаге структуры имя означает поле, на шаге variant — случай с этим именем.
После случая с данными путь может продолжаться по полям его payload и новым
случаям. Условия вычисляются слева направо с коротким замыканием: несовпадение
внешнего случая исключает все последующие casts.

`prism` и `prism_then` используют такие же постоянные дескрипторы, как `optic`
и `optic_then`. Их можно комбинировать при составлении пути; частичный путь
применяется операциями `prism_*`. Обновления `optic_*` и `prism_*` можно
чередовать в одном пайпе.

## Отсутствие значения

- `None` не совпадает с `some`.
- `JsonField.missing`, `null_value` и `present` остаются разными случаями.
  Обновление пути через `present` сохраняет Missing и null без преобразования.
- Несовпавший случай обычного variant сохраняется вместе со своими данными.
- При несовпадении `prism_over` не вызывает callback, а `prism_set` даже не
  вычисляет выражение замены. Они не создают отсутствующий payload и не
  переключают вариант. Для явного переключения используйте замену всего
  контейнера через `optic_set` или обычный конструктор variant.
- `prism_try_get` возвращает Some, если все шаги совпали. Поэтому чтение целого
  Option-поля может вернуть `Some(None)`: поле существует, его значение — None.

Для случаев без payload (`none`, `missing`, `idle`) используйте
`prism_matches`. Он также позволяет отличить `field.missing` от
`field.null_value`. `prism_try_get`, `prism_set` и `prism_over` требуют
ненулевой размер focus; для пустого маркера `JsonNull` используйте проверку
совпадения. Это также избегает ограничения SDK AOT для `Option<пустая структура>`.
В обычном variant имя `null_value` не имеет специального смысла: если его
payload — string, чтение возвращает `Option<string>`.

## Копирование и время жизни

`prism_try_get` клонирует только выбранное значение. Контейнер не обязан иметь
Clone. `prism_set`/`prism_over` клонируют весь заимствованный корень, включая
неизменённые owning-поля, и возвращают независимый результат. Для структур
нужен `[derive(clone=true)]` или собственная перегрузка `derive_clone`.

Даже при несовпадении обновление возвращает независимую копию. Поэтому Clone
корня всё равно выполняется и может вызвать пользовательские перегрузки или
исключение. Гарантия пропуска относится к modifier и выражению замены.

Временный owning-корень перемещается в следующий шаг без повторного Clone.
Он освобождается после snapshot/matches, в том числе при несовпадении и
исключении. В цепочке обновлений исходный заимствованный корень копируется
один раз. Заимствованная замена копируется, временная — перемещается.

Callback получает focus для чтения и возвращает значение того же типа.
Для owning-результата используйте `return <-`; reference-return запрещён.
Заимствованные входы не изменяются. Результат храните в `var inscope ... <- ...`
или передавайте следующему владельцу, как для обычных [Optics](OPTICS.md).

При исключении Clone/замены/callback освобождаются подготовленные внутренние
данные. Пользовательские Clone и callbacks отвечают за собственные локальные
выделения до передачи результата библиотеке. Внешние побочные эффекты не
откатываются. Автоматической валидации нет. Строки принадлежат контексту daScript.

Не выбирайте поле или payload из owning-временного контейнера до передачи
Prism: сохраните владельца в `var inscope` либо включите все шаги в путь.
Макрос диагностирует прямые проекции полей, элементов и `as case` из временного
владельца. Скрытые reference-return функции должны соблюдать обычные правила
времени жизни daScript.

## Проверки и ограничения

Поддержаны обычные структуры и именованные случаи variant. Индексы в пути,
traversal коллекций, указатели, классы и runtime-строки путей не поддерживаются.
Всё обновление контейнера по-прежнему доступно через Optics.

Тесты: [test_prism.das](tests/test_prism.das) и
[test_prism_exceptions.das](tests/test_prism_exceptions.das).
Они включены в `run.ps1 -Test`, `run.ps1 -Test -Jit` и `run_aot.ps1`.
Проверяются короткое замыкание, пропуск callback и фабрики замены, различия
состояний, независимость снимков и неизменённых полей, композиция обновлений,
однократное вычисление источников, исключения и точный возврат context heap
после прогрева. Проверка heap не измеряет string heap или память всего процесса.
Экспорт библиотеки проверяет Prism в независимом приложении.
