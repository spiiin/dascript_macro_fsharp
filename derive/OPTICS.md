# Optics: вложенные поля через пайпы

Optics добавляют чтение и функциональное изменение вложенных полей обычных
структур. Путь раскрывается в типизированные обращения к полям при компиляции:
во время выполнения нет поиска поля по строке и reflection.

```das
options gen2
require ./lib/derive.das

[derive(clone=true)]
struct Stats {health:int;bonuses:array<int>}
[derive(clone=true)]
struct Player {name:string;stats:Stats}

[export]
def main() {
    let health=optic("stats") |> optic_then("health")
    var inscope player=Player(name="Alice",stats=Stats(health=100))
    player.stats.bonuses <- [2,3]

    let hp=player |> optic_get(health)
    var inscope injured <- player |> optic_set(health,75)
    var inscope healed <- injured |> optic_over(health) <| $(hp:int) {return hp+10}
    verify(hp==100 && player.stats.health==100)
    verify(injured.stats.health==75 && healed.stats.health==85)

    // Даже поля, которые мы не меняли, принадлежат новой копии.
    healed.stats.bonuses[0]=99
    verify(player.stats.bonuses[0]==2 && injured.stats.bonuses[0]==2)

    // Чтение owning-поля тоже создаёт независимый снимок.
    var inscope snapshot <- player |> optic_get("stats")
    snapshot.bonuses[0]=10
    verify(player.stats.bonuses[0]==2)
}
```

Запускаемый пример: [optics_demo.das](examples/optics_demo.das).

## Операции

| Выражение | Результат |
|---|---|
| `optic("stats.health")` | Проверенный синтаксически постоянный путь |
| `optic("stats") \|> optic_then("health")` | Составной путь `stats.health` |
| `source \|> optic_get(path)` | Глубокий снимок выбранного поля |
| `source \|> optic_set(path,value)` | Независимый корень с заменённым полем |
| `source \|> optic_over(path) <\| $(value:T) {return ...}` | Независимый корень с результатом преобразования поля |

Пути должны быть строковыми литералами или неизменяемыми локальными константами.
Допустимы имена полей ASCII, разделённые точками; существование и тип каждого
поля проверяются при применении к корню. Используются имена полей daScript,
а не `json_name`. Один путь можно применить к разным совместимым структурам.
Это compile-time дескриптор пути, а не объект с функциями, который передаётся
как runtime lens. Параметр функции с произвольной строкой пути не поддерживается.

`optic_get` требует `derive_clone` только для выбранного поля: на корне
аннотация не обязательна. `optic_set` и `optic_over` для заимствованного корня
требуют глубокий Clone всего корня. Для структур включите `[derive(clone=true)]`
либо объявите собственную перегрузку `derive_clone`.

## Владение и исключения

- Переменная или поле стабильной переменной заимствуются. Изменение клонирует
  корень; входные данные и остальные владельцы сохраняют свои данные.
- Временный owning-корень передаёт владение. Поэтому в цепочке
  `player |> optic_set(...) |> optic_over(...)` исходный `player` копируется
  один раз, а второй шаг работает с уже независимым результатом.
- Заимствованное значение для `optic_set` глубоко копируется. Owning-результат
  вызова или литерал массива перемещается в новое поле.
- Функция `optic_over` получает поле для чтения и должна вернуть значение того
  же типа. Owning-результат возвращается через `return <-`; заимствованный
  reference-return запрещён. Для сохранения элементов массива клонируйте его
  внутри функции через `var result <- derive_clone(values)`.
- Возвращаемый owning-результат нужно хранить в `var inscope ... <- ...` либо
  явно передать следующему владельцу; не теряйте owning-результат выражения.
- Если Clone, замена или callback бросает исключение, подготовленный корень
  освобождается. `optic_get` освобождает переданный временный корень и при ошибке
  клонирования поля. Собственная перегрузка Clone обязана освобождать свой
  незавершённый результат перед исключением, как и в обычном derive Clone.
  Пользовательский callback также отвечает за свои локальные выделения до
  возврата: защита Optics освобождает данные, владение которыми уже передано ей.
- Отдельные побочные эффекты callbacks не откатываются. Проверка валидации не
  выполняется автоматически: при необходимости вызовите `derive_validate`.
- Строки принадлежат контексту daScript и следуют его времени жизни/GC;
  глубокая независимость здесь относится к owning-массивам и контейнерам.

Проекция из owning-временного значения вроде `make_player().stats` не сохраняет
владельца внешней структуры. Макрос выдаёт ошибку: используйте полный путь
`make_player() |> optic_get("stats.bonuses")` либо сначала сохраните владельца
в `var inscope player <- make_player()` и обращайтесь к его полю.

## Границы текущей реализации

Реализованы total lenses для полей обычных structs, без классов и наследования.
Массив, Option, JsonField и variant можно читать/заменять/преобразовывать целиком;
внутри `optic_over` их разбирают обычным daScript. Индексы в пути, обход всех
элементов (traversal), указатели и runtime-пути пока
не поддерживаются. Частичные пути через Option/JsonField/variant доступны
через [Prism](PRISM.md). Корнем может быть стабильный элемент массива структур,
например `players[0] |> optic_set("stats.health",80)`.

Это удобнее ручного кода, когда нужно сохранять исходные снимки и многократно
применять вложенные обновления. Для изменения единственного существующего
объекта на месте обычное `player.stats.health=80` остаётся дешевле: Optics
для заимствованного owning-корня копируют весь объект, а не только путь.

## Проверки

```powershell
./derive/run.ps1 -Test
./derive/run.ps1 -Test -Jit
./derive/run_aot.ps1
```

Проверяются независимость снимков/копий, владение Option/JsonField/variant,
фиксированные массивы, составные пути, законы get-put/put-get/put-put,
однократное вычисление источников, перенос промежуточных результатов,
исключения и возврат heap к прогретой исходной величине. Отрицательные тесты
проверяют диагностику путей и неподдерживаемых применений.
