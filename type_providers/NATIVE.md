# Ленивая генерация настоящих типов

`native_demo.das` объединяет ленивое раскрытие каталога с настоящими
номинальными структурами daScript. Проверено на Daslang 0.6.4.

```powershell
cd C:\src\dascript_macro_fsharp\type_providers
.\run.ps1
.\run.ps1 -Test
.\measure_native.ps1 -Count 10000
```

Прямой запуск: `daslang.exe native_demo.das -no-module-cache`.

## Типы и функции

В `native_functions.das`:

```das
typedef Player = provided_type("schemas/native", "Player")
typedef Team = provided_type("schemas/native", "Team")

def apply_damage(var player : Player; damage : int) {
    player.health -= damage
}

def get_team(player : Player) : Team {
    return player.team
}
```

В другом модуле, `native_demo.das`:

```das
typedef LocalPlayer = provided_type("schemas/native/../native", "Player")

var player = default<LocalPlayer>
var error : string
if (!try_load_native(fread("data/native_player.json"), player, error)) {
    panic(error)
}
apply_damage(player, 10)
let team = get_team(player)
let description = describe_team(team)
```

`Player` и `LocalPlayer` обозначают одну и ту же структуру. Имя типа содержит
нормализованный абсолютный путь каталога и имя схемы; перед созданием макрос
ищет уже зарегистрированную структуру во всей компилируемой программе.
Относительный путь задаётся от исходного файла с type macro. Используйте
одинаковое написание имени типа и регистра пути: отдельного сведения
симлинков, junctions и всех вариантов регистра в одну идентичность нет.

Поле `team` — настоящий вложенный `Team`, а не JSON-указатель. Возвращаемые
значения, аргументы и копии сохраняют типы. Тип с другим именем, даже с
полностью совпадающими полями, нельзя передать в `apply_damage`: это проверяет
`test_native_wrong_type.das`.

## Ленивость и зависимости

`AstTypeMacro.visit()` вызывается при разрешении `provided_type(...)`.
Провайдер читает только запрошенную схему и транзитивные зависимости её полей,
не перечисляя каталог. В демо генерируются `Team`, затем `Player` — каждый
ровно один раз. `UnusedBroken.json`, `CycleA.json` и прочие неиспользуемые
схемы не мешают компиляции.

```json
{ "name": "team", "type": "ref", "target": "Team" }
```

Здесь `ref` означает ссылку *схемы* на другой тип. В данных поле материализуется
по значению. Поэтому все зависимости запрошенной структуры необходимы, даже
если соответствующее поле не читается программой.

Циклы полей по значению отклоняются с диагностикой `by-value dependency cycle`.
В `Team` обратная связь с игроком представлена `leader_id : int`, чтобы не
создавать бесконечную вложенность. Владение указателями, nullable-ссылки,
восстановление графов по ID, массивы и циклические объекты не реализованы.
Существующий циклический каталог `schemas/world` относится к erased-примеру;
для этого варианта используется отдельный `schemas/native`.

`measure_native.ps1` создаёт каталог из 10 000 типов и запрашивает `Node0`,
содержащий `Node1`. Проверка требует ровно двух сгенерированных типов, хотя
`Node0` упоминается повторно под другим typedef и передаётся в функцию.

## Одна проверка при загрузке

`try_load_native` разбирает JSON и вызывает специализированный по типу декодер.
`apply_imm` разворачивает обход полей при компиляции. Во время загрузки
проверяется каждый требуемый объект и скаляр; поддержаны `string`, `int32`,
`bool` и вложенные структуры. Все поля обязательны. `null` и неверные типы
отклоняются, диапазон `int32` проверяется, лишние JSON-поля игнорируются.

Загрузка идёт во временную структуру. При ошибке результат остаётся прежним,
а `error` содержит путь, например `$.team.leader_id`. При успехе результат
присваивается целиком; при любом исходе временное JSON-дерево освобождается.
Строки имеют обычное время жизни строк daScript в контексте программы.

После загрузки `player.health` и `player.team.leader_id` — прямые обращения
к нативным полям. Нет поиска JSON-ключей, чтения схем и повторной проверки
данных при передаче между функциями. Повторный вызов загрузчика, естественно,
проверяет новый документ заново. Валидация проверяет форму и типы, но не
бизнес-правила вроде положительного здоровья или существования `leader_id`.

В отличие от erased-примера, этот вариант выделяет место для всей запрошенной
структуры и загружает все её поля и зависимости. Он подходит для повторного
чтения и изменения данных; ленивость здесь относится к генерации типов,
а не к чтению отдельных runtime-полей.

## Файлы и проверки

- `lazy_native_provider.das`: рекурсивное построение AST структур, повторное
  использование типов и диагностика циклов.
- `native_runtime.das`: специализируемый загрузчик с проверкой данных.
- `native_functions.das`: функции с типизированными аргументами и результатами.
- `native_demo.das`: повторный запрос типа и передача данных между модулями.
- `test_native_runtime.das`: ошибки вложенных данных, транзакционность,
  независимость копий и работа после освобождения JSON-дерева.
- Остальные `test_native_*.das`: ожидаемые ошибки компиляции.

`run.ps1 -Test` проверяет число созданных типов и непосредственный доступ к
полям в выводе компилятора `-log`. Все скрипты отключают межзапусковый AST-кеш
через `-no-module-cache`: отслеживание внешних файлов схем в кеше компилятора
и системе сборки остаётся задачей интеграции. Измерение AOT/JIT не выполнялось.
