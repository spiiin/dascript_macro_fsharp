# Отложенный Sequence

```das
require ./lib/computation.das
require ./lib/deferred_computation.das

var inscope task <- deferred(SequenceBuilder(), [10,20,30]) $(snapshot) {
    for (i in range(length(snapshot))) {
        snapshot[i] += 1
        yield snapshot[i]
    }
}

var inscope first <- task |> run_deferred
var inscope second <- task |> run_deferred
delete task

for (value in first) { print("{value}\n"); break }
for (value in second) { print("{value}\n") }
```

Полный пример — `deferred_sequence_demo.das`. Создание task не исполняет тело.
Каждый run_deferred создаёт отдельные builder/data и новый итератор: обычные
builder/data клонируются, а нулевой типовой дескриптор move-only builder
воссоздаётся без разыменования его маркера.
Тело Sequence начинает выполняться при первом next/обходе. Итераторы можно
обходить вперемешку; их изменения snapshot независимы. Удаление task не
отменяет уже созданные итераторы и не освобождает их снимки.

## Время жизни

У каждого запуска есть отдельная область памяти с builder и data. Ссылки на
snapshot в исходном CE раскрываются в доступ к этой области, а не в захват
стекового массива. Возвращённый итератор владеет ею до своего закрытия.

Порядок закрытия:

1. Закрыть внутренний итератор и выполнить его use_resource/try_finally.
2. Освободить снимок запуска.
3. Освободить служебные обёртки при закрытии владельца итератора.

Поэтому cleanup тела может читать snapshot. Закрытие до первого next тоже
освобождает снимок, но не приобретает ресурсы, объявленные в ещё не исполненном
теле. Пустая последовательность освобождает снимок при завершении обхода.

Поддержаны полное завершение, break/return из обычного for, явный sequence_close,
выход из inscope без запуска, исключение производителя и ошибка потребителя
при защищённом обходе. Повторное закрытие пустого владельца безопасно.

## Исключения при обходе

Для кода, который может бросить panic, используйте существующий sequence_each:

```das
var inscope seq <- run_deferred(task)
try {
    sequence_each(seq) $(value:int) {
        consume(value)
    }
} recover {
    // Итератор закрыт, его ресурсы и снимок освобождены.
}
```

sequence_each закрывает итератор при ошибке производителя и потребителя.
Обычный native for daScript при panic может оставить свой скрытый
итератор-владелец неосвобождённым. Ошибка производителя проходит через защиту
Sequence и освобождает снимок, но для гарантии очистки всех обёрток при
исключениях нужен sequence_each либо явное владение next/sequence_close.
Обычные завершение и break из for проверены без этого ограничения.

После ошибки одного итератора task можно запустить снова; остальные запуски
сохраняют свои снимки. Финализаторы самих снимков должны быть не бросающими.
Сохраняются прежние ограничения Sequence при исключениях из финализаторов и
изменение last_exception внутренним механизмом финализации; см. SEQUENCE.md.

## Типы и совместимость

Разрешён результат iterator<T>, если T является безопасным значением или
собственными данными. Встроенный move-only Sequence дополнительно допускает
`iterator<T&>` с владельцем текущего элемента (см. ниже). Остальные
элементы-ссылки, указатели и вложенные итераторы отклоняются: они могли бы пережить снимок после закрытия источника. Гарантия
независимости пользовательских clone/finalize остаётся частью их контракта.

Правила входных снимков прежние: они должны владеть данными; raw pointers,
blocks, lambdas, iterators и native handles в data/builder не допускаются.
Для встроенных move-only builders разрешён только их нулевой типовой маркер.
Поддержка определяется типом результата, а не именем SequenceBuilder, поэтому
совместимый сторонний builder тоже может вернуть итератор.

Value/Collect по-прежнему освобождают рабочий снимок сразу после завершения
run_deferred. Пайповые bind/yield_from, синтаксис deferred и обычный немедленный
computation не изменились. Планировщика и async-исполнения здесь нет.

## Проверки

- Два одновременно живых запуска, независимая мутация и удаление task до обхода.
- Счётчики уничтожения снимков и ресурсов; cleanup читает снимок до удаления.
- Полное завершение, break, return, закрытие без запуска и пустой Sequence.
- Повторные ошибки производителя/потребителя и возврат heap к исходному уровню.
- Sequence без data, отрицательный тест iterator с указателями в элементах.
- Прежние тесты отложенных Value/Collect, ошибок clone и порядка Run.

Тесты: test_deferred_sequence.das, test_deferred_iterator.das,
test_deferred_iterator_pointer.das. Запуск: `./run_computation.ps1 -Test`.

Вложенные iterator-источники `for`, `bind` и `yield_from` имеют отдельную
защиту закрытия: [SEQUENCE_NESTED_CLEANUP.md](SEQUENCE_NESTED_CLEANUP.md).
Пример: `sequence_nested_cleanup_demo.das`.

## Move-only элементы

`deferred(SequenceBuilder(type<T>), snapshot)` поддерживает move-only T с
полностью владеющими полями. Новый итератор каждого запуска удерживает
свой снимок до закрытия, включая break, producer/consumer error и отсутствие
обхода. Тип результата — `iterator<T&>` с временным заимствованием owning-slot;
забрать элемент можно через `<-`. Исключение из запрета reference-result
ограничено встроенным MoveSequenceContext и соответствующим ему типом T.

Пример и условия владения: [MOVE_COLLECTIONS.md](MOVE_COLLECTIONS.md),
`deferred_move_collections_demo.das`.
