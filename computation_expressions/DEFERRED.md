# Отложенные и повторно запускаемые CE

```das
require ./lib/computation.das
require ./lib/deferred_computation.das

var inscope amounts <- [10,20,30]
var inscope reward <- deferred(ResultBuilder(), amounts) $(snapshot) {
    let total = result_ok(snapshot[0]+snapshot[1]+snapshot[2]) |> bind
    snapshot[0] = 999
    return total+5
}

delete amounts
let first = reward |> run_deferred
let second = reward |> run_deferred
assert(first as ok == 65 && second as ok == 65)
```

`deferred_demo.das` возвращает такое вычисление из функции: исходный массив
уже уничтожен к моменту запуска. Пайповые bind, and_bind, return_from, ветвления,
циклы и ресурсы раскрываются тем же макросом computation и сохраняют его
оптимизации. Подключение — отдельный модуль `deferred_computation`.

## Создание и запуск

- `deferred(builder, data) $(snapshot) { ... }` создаёт вычисление с явным снимком.
- `deferred(builder) { ... }` создаёт вычисление без входных данных.
- `run_deferred(task)` или `task |> run_deferred` запускает тело.

При создании builder и выражение data вычисляются один раз, слева направо.
Затем их данные клонируются во владеющее хранилище. Тело CE, его bind, Delay,
Run и захват ресурсов ещё не выполняются. Пользовательская операция clone,
если она определена, выполняется при создании снимка.

Каждый запуск клонирует сохранённые builder и data в отдельный рабочий снимок
и исполняет обычный computation. Поэтому локальные переменные тела и состояние
StateBuilder начинаются заново, а изменение snapshot не влияет на следующий
запуск. Это повторное исполнение, не кеширование результата. Глобальные данные,
вызовы внешних функций и их побочные эффекты не откатываются.

Снимок передаётся через один **нетипизированный** аргумент `$(snapshot)`:
тип выводится из data. Для нескольких значений передайте tuple или структуру.
Имена аргумента и внешнего источника лучше различать: действуют обычные правила
daScript против затенения переменных.

Тело оформлено внутренней функцией без неявных захватов. Обращение к внешней
локальной переменной, которую не передали в data, отклоняется компилятором.
Глобальные переменные доступны и читаются при запуске, как в обычной функции.

## Владение и время жизни

Вычисление — перемещаемый владелец, а не копируемая ссылка на lambda:

```das
var inscope task <- make_reward()
var inscope transferred <- task
let result = run_deferred(transferred)
```

После перемещения исходный task пуст. Его запуск выдаёт runtime-ошибку.
Копирование через `=` запрещено типом. Владелец освобождает сохранённые данные
при `delete`/обычном выходе из inscope, в том числе если ни одного запуска
не было. Поля внутреннего tuple и итератор-владелец не являются API: не извлекайте
из них служебную lambda и не управляйте ею отдельно.

Массивы, таблицы, tuples и структуры с собственными данными клонируются согласно
операции `:=` daScript. Собственная перегрузка clone должна обеспечивать
независимость данных. Указатели, native handles, blocks, lambdas и iterators
в builder/data отклоняются, включая вложенные поля: их простая копия не даёт
гарантии времени жизни. Пользовательские финализаторы снимков не должны бросать
исключения. Строки остаются в модели памяти текущего контекста daScript;
перенос вычисления между Context не поддержан.

Рабочие снимки Value/Collect удаляются после каждого запуска, также при native
panic и ошибке clone. Для возвращённого итератора снимок живёт до его закрытия. После неуспешного запуска сохранённое вычисление остаётся пригодным
для следующей попытки. Ресурсы тела приобретайте через use_resource/try_finally:
они принадлежат конкретному запуску, а не сохранённому вычислению.

Как и в остальном daScript, native panic пропускает обычный inscope вызывающего
кода. Если вы собираетесь перехватить ошибку и повторить запуск, держите task
**снаружи** try/recover:

```das
var inscope task <- make_reward()
try { let result = run_deferred(task) } recover { /* task всё ещё жив */ }
```

Освобождение владельца использует существующий механизм финализации Sequence:
он сбрасывает управляющие флаги генератора через внутренний panic/recover.
Из-за этого удаление владельца может менять this_context().last_exception;
сообщение об ошибке запуска сохраняйте до удаления task, если оно нужно позже.

## Результат и текущие границы

Поддержаны вычисления, возвращающие значения или собственные коллекции:
Result, Option, Validation, State/Writer и их комбинации, List, а также
совместимые сторонние builders, включая ReportBuilder и его ce_run.
Они должны поддерживать соответствующие обычные операции computation.

Результат с собственной коллекцией забирайте перемещением:

```das
var inscope values <- run_deferred(task)
```

Коллекции двух запусков независимы и могут жить после удаления task.
Sequence поддержан: каждый run_deferred возвращает новый итератор,
владеющий своим рабочим снимком до закрытия. Снимок освобождается после
ресурсов тела. Произвольные указатели/ссылки, lambdas и вложенные итераторы
в элементах не допускаются. Исключение — встроенный move-only Sequence с
владеющим слотом и публичным iterator<T&>; его особый контракт описан в
[DEFERRED_SEQUENCE.md](DEFERRED_SEQUENCE.md). Примеры, порядок очистки и защищённый обход при исключениях:
[DEFERRED_SEQUENCE.md](DEFERRED_SEQUENCE.md).

Deferred не добавляет потоки или async-ожидание. Value/Collect выполняются
синхронно при run_deferred, Sequence/Coroutine возвращают ленивый итератор.
Deferred-корутины можно передать отдельному планировщику с отменой:
[COROUTINE_SCHEDULER.md](COROUTINE_SCHEDULER.md). Обычные Value/Collect CE
выполняются немедленно.

## Проверки

- test_deferred.das: возврат из функции, создание без исполнения тела,
  удаление до первого запуска, повторный запуск, мутация исходника/снимка,
  независимость результатов List, перемещение, остановка при Error/None,
  ресурсы и повторные исключения без роста heap.
- test_deferred_snapshots.das: структура с массивом, начальное состояние
  StateBuilder, исключения clone при создании и запуске, последующее успешное
  повторение, освобождение частично созданных снимков.
- test_deferred_order.das: порядок builder/data, отсутствие runtime-вызова
  ce_protocol, выполнение тела/Return/Run только на каждом запуске.
- Отрицательные тесты: неявный захват локальной переменной, pointer в структуре,
  небезопасные элементы iterator, аннотация snapshot и копирование владельца.

`./run_computation.ps1 -Test` запускает эти проверки; `../run.ps1 -Test` включает
также полную регрессию type providers.
