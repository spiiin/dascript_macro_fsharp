# WhenAll для массива задач

`task_when_all(tasks)` потребляет динамический массив задач с одинаковым типом
результата T. Опрос идёт по индексам слева направо, не более одного раза на ребёнка
за poll родителя. Завершённые дети повторно не опрашиваются. Результаты сохраняют
порядок входного массива, независимо от порядка завершения.

```das
var jobs:array<typedecl(task_after_polls(0,0))>
jobs |> emplace(task_after_polls(2,10))
jobs |> emplace(task_after_polls(0,20))
jobs |> emplace(task_after_polls(1,30))
var inscope batch <- task_when_all(jobs) // jobs теперь пуст.
verify(task_poll(batch)==TaskStatus.Waiting)
verify(task_poll(batch)==TaskStatus.Waiting)
verify(task_poll(batch)==TaskStatus.Succeeded)
var inscope values <- task_value(batch) // Независимая копия [10,20,30].
```

Нужно подключить `./lib/task_combinators.das` или `./lib/task_scheduler.das`.
Перегрузка `task_when_all(left,right)` остаётся прежней: два разных типа результата
и tuple first/second. Для массива все дети имеют один тип.

## Пайповый bind и владение результатом

Массивы daScript — move-only. Поэтому агрегат возвращает отдельную **владеющую
задачу коллекции**, управляемую теми же task_poll/status/error/cancel/value.
Обычный TaskBuilder(type<T>) по-прежнему требует копируемый T; произвольный
TaskBuilder(type<array<T>>) этим изменением не добавляется.

В CE массив доступен через заимствование:

```das
var source <- computation(TaskBuilder(type<int>)) {
    var results & = task_when_all(make_jobs()) |> bind
    task_delay_ms(10) |> bind
    return results[0]+results[1]
}
```

Агрегат владеет массивом всё время выполнения продолжения, включая последующие
ожидания. Завершение, отмена или исключение продолжения закрывают источник bind
и освобождают массив. Ссылку results нельзя сохранять дольше этой области.
Для других Task reference-bind по-прежнему запрещён; разрешение предоставляется
отдельной операцией протокола ce_await_borrow_value.

Вне CE `var inscope values <- task_value(batch)` возвращает независимый clone
массива. Его можно изменять и хранить после удаления batch или записи scheduler;
повторный task_value возвращает ещё одну копию. До Succeeded task_value вызывает
panic. Внутренние control/value агрегата не являются API: не изменяйте их напрямую,
особенно не меняйте размер внутреннего массива во время опроса.
При Failed/Cancelled буфер частичных результатов освобождается сразу; успешный
кеш остаётся до удаления владельца или записи scheduler.

Пустой массив с известным типом детей возвращает Succeeded с пустым результатом
при первом poll. Создание агрегата не исполняет тела детей. Уже успешные дети
передают закешированные значения; задача, находящаяся в процессе poll, отклоняется
до перемещения входного массива. После успешной передачи входной массив пуст;
старые ссылки на его элементы использовать нельзя.

## Планировщик, время и отмена

Агрегат можно ожидать из обычной Task или зарегистрировать напрямую:

```das
var inscope scheduler <- task_scheduler(type<array<int>>)
let id=task_spawn(scheduler,task_when_all(make_jobs()))
// После Succeeded:
// var inscope values <- task_value(scheduler,id)
```

Поддержаны TaskTimeout, task_with_cancellation, task_scope, task_scheduler_scope,
перенос владельца scheduler, forget/prune и удаление. TaskDelay внутри детей
использует текущий now_ms того же tick. Опрос агрегата считается **одним** опросом
бюджета scheduler, даже если внутри он проверяет много детей; лимит не ограничивает
размер массива и длительность синхронного кода отдельного ребёнка.

Запрос токена замечается при очередном опросе обёртки; таймауты по-прежнему
срабатывают до poll независимо от бюджета. Отмена или удаление агрегата закрывает
всех незавершённых детей, включая ещё не опрошенных. Часы для cleanup не требуются.

## Ошибки и порядок эффектов

Первый наблюдённый Failed даёт Failed родителя; последующие индексы в этом poll
не запускаются, незавершённые владельцы закрываются. Cancelled ребёнка передаётся
родителю как Cancelled, без запуска продолжения и перехвата в try_with.
Оставшиеся дети закрываются по индексам; ребёнок, завершившийся или упавший при
poll, может выполнить свой cleanup раньше остальных.

Ошибка close-callback не мешает закрыть остальных. Уже наблюдённая native-ошибка
сохраняется; если её нет, первая ошибка cleanup даёт Failed вместо обычной отмены.
Raw delete/inscope освобождает владельца без выброса из native finalizer; для
чтения диагностики используйте явный poll/cancel/task_scope до удаления.
Ограничения произвольных бросающих native finally/ce_dispose остаются прежними.

`Result.error` внутри T является обычным значением. Все такие дети ожидаются,
результат — массив Result<T>. TaskResultBuilder тоже может заимствовать этот
массив, но не разворачивает и не объединяет ошибки отдельных элементов.
Специализированный task_result_when_all(array) этим изменением не добавляется.

Элементы результатов должны быть копируемыми и владеть данными; указатели и
исполняемые captures не принимаются. Поддержаны в том числе string и CeUnit.
Массивы агрегатов, пары/race с агрегатом как move-only результатом и произвольные
move-only элементы требуют отдельного расширения; обычные копируемые T остаются
границей этой версии.

## Расходы и проверки

Входной массив передаётся перемещением. Результирующий буфер размера N выделяется
один раз; успешные значения записываются по исходным индексам. На каждом poll
проверяется N статусов и опрашиваются только незавершённые дети. Владелец добавляет
генератор Task<Unit>; новых потоков и фоновых jobs нет.
Bind заимствует результат без копии массива; каждый task_value делает clone O(N).

[task_array_demo.das](examples/task_array_demo.das) показывает завершение загрузок
в порядке 1,2,0 и чтение результатов в порядке 0,1,2 через пайповый bind.

[test_task_array.das](tests/test_task_array.das): порядок, пустой/одноэлементный
массив, cached results, string/Unit/Result, независимые копии, scheduler и loan
через следующее ожидание. [test_task_array_lifetime.das](tests/test_task_array_lifetime.das):
ошибки, отмена до/после старта, cleanup с ошибкой, token, timeout, panic хоста,
удаление, отказ передачи исполняющегося ребёнка и 32 повторения со стабильным heap.
