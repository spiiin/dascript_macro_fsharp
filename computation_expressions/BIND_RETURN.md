# BindReturn

Синтаксис CE не меняется:

```das
let result = computation(ResultBuilder()) {
    let level = result_ok(12) |> bind
    return "Level {level}"
}
```

Для соседних bind и завершающего обычного return макрос теперь выбирает
`ce_bind_return(builder, source, mapper)`. Mapper вычисляет обычное значение,
например строку, без предварительной упаковки через `ce_return`.

До оптимизации:

```text
ce_bind(builder, source, x => ce_return(builder, expression(x)))
```

С оптимизацией:

```text
ce_bind_return(builder, source, x => expression(x))
```

Примеры Result, Option, Validation, List и сочетания с and_bind:
`bind_return_demo.das`.

## Когда применяется

- `let x = source |> bind` непосредственно перед `return expression`;
- bind без переменной перед return;
- последняя пара bind/return в цепочке зависимых bind;
- группа `a |> and_bind(b) |> bind` перед return;
- такие же пары внутри поддерживаемых вложенных CE scope.

Оптимизация не перескакивает через промежуточные инструкции, ветвления или
циклы. `return ... |> return_from` не преобразуется. Явный move/ref-return
также не является кандидатом. Sequence использует отдельный generator backend
и не изменён.

Исходное объявление переменной копируется в mapper: сохраняются имя, `let`/`var`
и явная аннотация типа. Несовместимая аннотация по-прежнему даёт ошибку компиляции.

## Протокол и совместимость

Необязательная перегрузка builder имеет форму:

```text
ce_bind_return(builder, source : M<T>, mapper : block<(value:T):U>) : M<U>
```

`M<T>` здесь — условное обозначение результата. Перегрузка обязана сохранять
поведение `ce_bind(builder, source, x => ce_return(builder, mapper(x)))`:
успех/неуспех, эффекты, порядок, число вызовов mapper и исключения.

В `builder_protocol` есть общий типовой fallback, возвращающий служебный
`CeBindReturnFallback`. Макрос выводит тип вызова, затем через compile-time
условие выбирает специализированный BindReturn или **исходное раскрытие
Bind/Return в вызывающем модуле**. Сам fallback не выполняется. Нет runtime
проверки наличия функции, дополнительного вычисления источника или регистрации
имени builder в макросе.

Не вызывайте типовой fallback вручную как пользовательскую операцию.
Для расширения достаточно определить подходящую перегрузку `ce_bind_return`
в своём модуле. Служебный тип `CeBindReturnFallback` зарезервирован для
отсутствия оптимизации. Builders без перегрузки продолжают работать, включая
собственные builders и Collect с владеющим результатом.

## Реализации

Специализированные перегрузки добавлены для:

- Result: при Error mapper не вызывается;
- Option: при None mapper не вызывается;
- Validation: invalid сохраняется целиком, mapper не вызывается;
- Writer: сохраняется журнал исходного значения;
- Reader: mapper получает окружение либо payload источника;
- List: один проход по источнику с заполнением итогового массива;
- State: снимок StateGet, StatePut и готовый результат со состоянием;
- StateResult: те же операции плюс обычный Result и откат на Error;
- WriterResult: готовый WriterResult, обычный Result и tell.

Все перечисленные Value-builders и List теперь имеют специализированные
перегрузки. Fallback сохраняется для сторонних builders без BindReturn.

## List и владение

Обычный Bind с Return создавал промежуточный одноэлементный массив для каждого
элемента, после чего копировал его в общий результат. Специализированный
`ce_list_map` сразу добавляет значение mapper в общий массив.

Фиксированные и динамические массивы поддержаны. Заимствованные источники
сохраняются; временные источники принадлежат сгенерированному scope и
освобождаются после обхода. При panic в mapper освобождаются частично собранный
результат и временные источники. Обход по индексам не оставляет массив
заблокированным при исключении. Размер источника не следует менять во время
обхода.

Для Result/Option и других маленьких контейнеров компилятор мог уже эффективно
встраивать обычную цепочку. Здесь не заявляется измеренный процент ускорения;
для List устранено создание промежуточных массивов в реализации.

## Проверки

`run_computation.ps1 -Test` включает:

- `test_bind_return_dispatch.das`: счётчики доказывают вызов специализированной
  операции, отсутствие Bind/Return на быстром пути, fallback внешнего builder,
  отсутствие оптимизации через промежуточный эффект и для return_from;
- `test_bind_return.das`: отсутствие вызова mapper при Error/None/invalid,
  однократные источники, работа fallback Collect, сохранение входных массивов,
  cleanup ресурса, отсутствие роста heap при повторных исключениях;
- `test_bind_return_types.das`: совпадение типов обычного и быстрого пути,
  включая вложенные tuple, а также результатов Writer и List;
- прежние тесты состояния, отката, журнала, and_bind, ресурсов, аннотаций и
  несовместимых типов.

Раскрытие можно посмотреть через
`daslang.exe examples/bind_return_demo.das -no-module-cache -log`: List использует
`ce_list_map`.


## State, StateResult и WriterResult

`effect_bind_return_demo.das` показывает обучение персонажа, отклонённую
награду с откатом и журнал успешной награды. Пайповая запись не меняется.

StateGet сохраняет снимок перед mapper. StatePut и готовый state-результат
сначала обновляют состояние builder, затем вызывают mapper. Итоговый результат
берёт состояние после mapper — в том же порядке, что прежние Bind/Return.

StateResult при Error восстанавливает `builder.initial` целиком и не вызывает
mapper. Состояние из ошибочного вложенного результата не принимается.
При native panic автоматического отката по-прежнему нет; ресурсные scopes
выполняют обычную очистку. Error-результат теперь явно инициализируется через
`default<R>`, что поддерживает структуры состояния с начальными значениями полей.

WriterResult сохраняет журнал исходного результата и ранее выполненных шагов,
включая запись, сопровождающую Error. Mapper не вызывается при Error. Для
успешного результата больше не нужна конкатенация журнала с пустой строкой
от Return. Lift обычного Result и tell также имеет прямую реализацию.

`test_effect_bind_return.das` сравнивает быстрый и обычный путь для всех десяти
форм источников, в том числе типы вложенных tuple. Compile-time проверки
подтверждают наличие специализированных перегрузок. Дополнительно проверены
счётчики mapper, откат, порядок журнала, изменение состояния внутри mapper,
исключение после StatePut и очистка ресурсов. Измеренный процент ускорения
для этих небольших контейнеров не заявляется.

Следующий быстрый путь — `ce_bind2_return` для `and_bind → return`.
Result/Option/Validation обходятся без контейнера объединённой пары, List —
без массива всех пар. Подробности: [BIND2_RETURN.md](BIND2_RETURN.md).
