# and_bind и MergeSources

Общий маркер `and_bind` объединяет независимые источники перед обычным bind:

```das
require ./lib/computation.das
require ./lib/validation_builder.das

let result = computation(ValidationBuilder()) {
    let fields = (check_name(name)
        |> and_bind(check_level(level)) |> bind)
    return Character(name=fields.first, level=fields.second)
}
```

Bind остаётся пайпом. Для переноса пайпового выражения на несколько строк
используйте скобки, как в примере. Игровые примеры Result, Option, Validation и List:
`and_bind_demo.das`.

## Семантика

| Builder | Успех | Неуспех |
| --- | --- | --- |
| Validation | valid пары `.first`, `.second` | Ошибки обоих источников, слева направо |
| Result | ok пары | Первая ошибка в порядке источников |
| Option | some пары | None, если отсутствует любой источник |
| List | Все пары: внешний цикл слева, внутренний справа | Пустой список, если любой источник пуст |
| ReaderResult | ok пары из Result/reader_ask() | Первая ошибка в порядке источников |
| MoveResult / MoveOption | Перемещение payload в пару | Error / None с освобождением принадлежащих merge значений |

Все источники достигнутой группы вычисляются слева направо ровно один раз,
включая случай Error/None/invalid/пустого списка. Это независимые вычисления:
значение первой проверки ещё не доступно второй. Группа не запускает потоки.
Native panic прерывает вычисление сразу, оставшиеся источники не запускаются.
Если предыдущий обычный bind остановил CE, группа вообще не вычисляется.

Полная матрица builders и границы владения: [CE_SEMANTICS.md](CE_SEMANTICS.md). Move-only объединение описано в [MOVE_CE.md](MOVE_CE.md). Демонстрационные ReportBuilder и GameSourceBuilder также делегируют объединение Result-протоколу.

После объединения обычный `ce_bind` решает, запускать ли продолжение.
Result/Option/Validation запускают его только при успехе; List — один раз
для каждой пары. Без переменной тоже можно:

```das
first_check() |> and_bind(second_check()) |> bind
```

Для трёх источников:

```das
let group = a |> and_bind(b) |> and_bind(c) |> bind
// group.first.first — a; group.first.second — b; group.second — c
```

Группировка сохраняет вложенные пары, а не создаёт плоский tuple.
Также допустима вложенная правая группа `a |> and_bind(b |> and_bind(c)) |> bind`.
Маркер поддерживается в дереве источника, непосредственно завершающемся bind.
Он не является runtime-функцией и не может сохраняться в переменную без bind
или использоваться как произвольная функция внутри другого выражения.

## Расширение протокола

Builder добавляет перегрузку:

```text
ce_merge_sources(builder, left : M<A>, right : M<B>) : M<tuple<first:A;second:B>>
```

Здесь `M<T>` — обозначение контейнера, не буквальный синтаксис daScript.
Фактический тип может быть любым, если соответствующий `ce_unwrap` выводит
payload, а `ce_bind` умеет его обработать. Имена `.first` и `.second` — соглашение
четырёх стандартных реализаций. `ce_source_pair(a,b)` создаёт такую пару,
снимая const/ref-квалификаторы с типов её полей.

Никакой проверки имени конкретного builder в макросе нет. Отсутствующая
перегрузка или смешивание несовместимых контейнеров даёт ошибку компиляции.
`test_and_bind_external.das` добавляет перегрузку для ReaderBuilder в вызывающем
модуле и использует только `computation_macro` + `reader_builder`.

`and_bind` поддержан для стратегий Value и Collect. Generator-стратегия
Sequence пока не поддерживает этот маркер. Встроенная Validation-перегрузка
вызывает прежнюю `validation_zip`; её прямое использование тоже сохранено.

## Порядок и владение

Макрос раскрывает группу в вложенные продолжения: вычислить левый источник,
вычислить правый, вызвать `ce_merge_sources`, затем `ce_bind`. Типовые probes
не выполняют исходные выражения. Объединённый источник остаётся жив до конца
вызова bind.

List принимает фиксированные и динамические массивы, в том числе смешанные.
Тип элементов источников может отличаться от типа итогового ListBuilder:
например, `int` и `string` могут дать список `string`.

Входные массивы, переданные по ссылке, заимствуются и сохраняют содержимое.
Временные массивы из литералов/функций и промежуточные произведения принадлежат
сгенерированному scope. Они освобождаются при нормальном возврате и исключении
в следующем источнике или продолжении. Выбор владения использует выведенную
ссылочность выражения, а не только форму AST. Collect-результаты должны
поддерживать перемещение и удаление, как требует основной протокол.

List материализует произведение: два источника длины N и M требуют памяти
на N*M пар. Цепочки также материализуют промежуточные пары. Это не ленивый zip
по одинаковым индексам. Элементы источников должны быть копируемыми.

Bind списка обходит источник по индексам: native iterator оставлял массив
заблокированным при исключении из продолжения и мешал освобождению временных
групп. Не меняйте размер источника во время его обхода.

## Проверки

`run_computation.ps1 -Test` и общий `../run.ps1 -Test` включают:

- ошибки/успех четырёх builders, порядок и однократность источников;
- три источника, разные типы payload, bind без переменной, остановку циклов;
- декартов порядок List, пустые источники, фиксированные/динамические массивы;
- сохранение и повторное использование заимствованных массивов;
- проверку heap до/после повторных запусков, включая ошибку в источнике,
  ошибку в продолжении и cleanup ресурсов;
- перегрузку внешнего builder и отрицательные проверки неправильной арности,
  несовместимых контейнеров, отсутствующей перегрузки и отсутствующего bind.

При соседнем обычном return теперь доступен быстрый путь Bind2Return для
Result, Option, Validation и List. List сохраняет снимки источников, но не
создаёт массив всех пар. Остальная семантика группы сохраняется.
См. [BIND2_RETURN.md](BIND2_RETURN.md).

## Bind2

Группы and_bind с произвольным продолжением используют необязательный
`ce_bind2` для Result, Option, Validation и List. Синтаксис прежний;
старые builders сохраняют fallback через MergeSources и Bind.
См. [контракт и ограничения](BIND2.md) и `bind2_demo.das`.
