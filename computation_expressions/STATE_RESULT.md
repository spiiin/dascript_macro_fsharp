# StateResultBuilder: состояние с откатом при Error

```das
require ./lib/computation.das
```

`StateResultBuilder(initial)` создаёт синхронный workflow с локальным состоянием
и исходным снимком. Результат:

```text
tuple<result : variant<ok : T; error : string>; state : S>
```

При успехе state — конечное состояние. При Error state — исходное состояние
**всей computation**, включая изменения до последней ветки/цикла/дочернего шага.
Все последующие шаги пропускаются. Исходный аргумент initial не изменяется для
состояния из независимых копируемых значений.

## Игровой пример

`game_transaction.das` содержит `AdventureState` и `adventure_turn`.
Шаги: потратить 10 золотых, купить зелье, выпить его, увеличить число ходов,
получить урон, проверить выживание. Все изменения сделаны через пайпы:

```das
let outcome = computation(StateResultBuilder(initial)) {
    var game = state_get() |> bind
    game.gold -= 10
    game.health += 20
    state_put(game) |> bind

    var injured = state_get() |> bind
    injured.health -= damage
    state_put(injured) |> bind
    check_alive(injured.health) |> bind
    return "turn completed"
}
```

`state_result_demo.das` запускает полный пример с состоянием
`health=50, gold=30, potions=2, turns=0`:

```text
Success: health=60, gold=20, turns=1
Error: hero defeated; rollback: health=50, gold=30, turns=0
```

В обоих случаях initial остаётся прежним. На ошибочном пути счётчик reached
показывает, что изменения выполнялись до проверки. Он находится вне состояния
и намеренно не откатывается.

## Источники bind

| Источник | Поведение |
|---|---|
| `state_get()` | Передать копию текущего состояния |
| `state_put(new_state)` | Заменить текущее состояние, передать Unit |
| Обычный `Result<T>` | На Ok передать значение; на Error откатить состояние и остановиться |
| `StateResult<T,S>` | На Ok принять состояние дочернего результата; на Error откатить к начальному состоянию текущего workflow |

`state_put` и `state_get` создают описания операций; выполняет их bind.
Несвязанный `let op = state_put(...)` не изменяет состояние.
`return value` возвращает Ok(value) и текущее состояние.
`return prepared |> return_from` поддерживает обычный Result и StateResult;
Error в обоих случаях вызывает откат. Без return_from возвращённый Result
остаётся обычным вложенным payload и не запускает откат.

Zero — Ok(Unit) с текущим состоянием. Combine распространяет Error и откат
через промежуточные ветки. Циклы накапливают состояние успешных итераций,
но Error откатывает и все эти итерации, и изменения перед циклом.
Работают for/while, вложенные циклы, завершающие ветки и блоки без return.
Тела циклов и промежуточные ветки по-прежнему должны возвращать Unit.

## Дочерние workflow и границы отката

```das
let parent = computation(StateResultBuilder(initial)) {
    state_put(intermediate) |> bind
    let current = state_get() |> bind
    let value = child(current) |> bind
    return value
}
```

У child свой начальный снимок current. Ошибка в child возвращает его снимок.
Но bind в parent восстанавливает **initial родителя**, а не current ребёнка.
Успех child принимает его состояние; более поздняя ошибка parent откатывает
и эти изменения. Это принятие результата внутри ещё не завершённой внешней
операции, не независимый коммит во внешнее хранилище.

Просто вычислить child без bind — значит получить отдельный результат.
Ни его успех, ни его ошибка сами по себе не меняют контекст parent.
Если ошибочный готовый StateResult содержит другой снимок state, внешний
builder игнорирует этот снимок и возвращает собственный initial.

## Конструкторы и композиция

```das
state_result_ok(42, state)
state_result_error("failed", type<int>, state)
state_result_value(result_ok(42), state)
```

Эти конструкторы создают данные; сами по себе они не запускают откат.
Откат обеспечивает builder при bind/return_from и распространении ошибки.

Обычный результат StateBuilder `{value, state}` автоматически не поднимается:
его можно явно преобразовать через
`state_result_ok(previous.value, previous.state)`.
Option, Writer и WriterResult также требуют явного решения о преобразовании.
Состояние источника должно иметь тот же тип S, что и состояние builder.

Обычное computation выполняется немедленно. Для сохранения и повторного запуска
есть deferred (см. DEFERRED.md). Для нового немедленного запуска вызывайте функцию с другим initial;
повторный bind уже готового результата импортирует снимок, не переигрывая шаги.
Отдельные computation не разделяют локальный контекст.

## Границы гарантии

Откат основан на копировании значения состояния, а не на журналировании всех
изменений памяти. Используйте состояния из независимых копируемых значений,
как числовые поля игрового примера. Указатели и разделяемые изменяемые объекты
не клонируются глубоко: изменение объекта за ссылкой не откатывается этим
builder. Move-only состояния и payload не поддержаны.

Откатывается только переданное состояние. Печать, внешние счётчики, файлы,
сетевые операции и прочие внешние эффекты не отменяются. Исключения/panic языка
не превращаются автоматически в Error: контракт отката относится к значению Error.
Для явного перехвата есть try_with (см. TRY_WITH.md); сам panic не откатывает
состояние, но возврат Error из обработчика запускает обычный откат. Тип ошибки
пока string. Этот builder синхронный, без отмены и сохранения состояния во
внешнее хранилище.

## Реализация и тесты

`state_result_builder.das` реализует перегрузки существующего протокола.
Контекст хранит kind, initial и state. Макрос уже создаёт локальную изменяемую
копию builder. `sr_failure` восстанавливает state и формирует ошибочный
результат с initial, сохраняя сообщение ошибки и меняя только отсутствующий
тип успешного payload. AST-преобразование менять не потребовалось.

```powershell
cd C:\src\dascript_macro_fsharp\computation_expressions
.\run_computation.ps1 -Test
```

`test_state_result.das` проверяет успех и сбой на каждой позиции, откат всех
изменений, точное число вызовов, исходный текст ошибки, переход int -> string,
ветви, пустые/вложенные/завершающие циклы, 10 000 итераций, снимки состояния,
независимые повторные запуски, вложенные границы отката, ошибку после успешного
дочернего шага, обе формы return_from и пропуск источников/условий после ошибки.

Негативные тесты `test_state_result_option.das`,
`test_state_result_wrong_type.das`, `test_state_result_foreign_state.das`,
`test_state_result_loop_value.das` проверяют несовместимые источники, типы
состояния и не-Unit результат итерации. Общий `../run.ps1 -Test` включает все проверки.

Для очистки ресурсов при завершении и panic используйте [Using/TryFinally](RESOURCES.md); panic по-прежнему не преобразуется в Error.
