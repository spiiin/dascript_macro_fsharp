# SequenceBuilder: ленивые последовательности

`require computation` подключает `SequenceBuilder`. Результат — нативный
однопроходный `iterator<T>`, а не массив и не повторно перечисляемый F# `seq<T>` (для move-only T используется
владеющий вариант iterator<T&>, описанный ниже).
Для нового обхода нужно снова вызвать функцию, создающую computation.

```das
var inscope values <- computation(SequenceBuilder()) {
    let x = [1,2] |> bind
    let y = [10,20] |> bind
    yield x+y
}
for (value in values) { print("{value}\n") }
// 11, 21, 12, 22
```

`SequenceBuilder()` выбирает `int`; для другого типа используйте
`SequenceBuilder(type<T>)`. Для копируемого T результат — iterator<T>.
Для move-only T публичный результат — iterator<T&>, владеющий текущим элементом:
подробности заимствования и перемещения в [MOVE_COLLECTIONS.md](MOVE_COLLECTIONS.md).
Выражение builder вычисляется один раз при создании итератора. Тело начинает
работать только при обходе. Каждый `yield` приостанавливает его; локальные
переменные и позиция циклов сохраняются. При `break` остаток не выполняется.
Храните результат в `var inscope ... <- ...` и не копируйте итератор.

Поддерживаются:

- `yield expression`: выдать одно значение и продолжить при следующем запросе;
- `expression |> yield_from`: последовательно выдать значения источника;
- `let x = source |> bind`, `var x = source |> bind`, `source |> bind`:
  выполнить оставшуюся часть текущего блока для каждого элемента источника;
- `if/else`, `for`, `while`, пустые блоки, обычные локальные вычисления;
- нативные источники `for`: массивы, диапазоны и итераторы, включая вложенные computation.

Пустой источник bind пропускает его продолжение; пустой yield_from позволяет
перейти к следующим инструкциям. Никакой промежуточный массив результатов не
строится. Источник bind вычисляется лишь при достижении этого шага, один раз
на вход в соответствующий цикл. Бесконечный источник допустим: см. игровой
пример `sequence_demo.das`, который запрашивает только три уровня противника.

Отличия и ограничения:

- `return`/`return_from` для SequenceBuilder запрещены: выдача записывается через
  `yield`/`yield_from`. `return false`, завершающий нативный generator, добавляет макрос.
- Копируемые внешние значения захватывает нативный generator. Проверка в
  `test_sequence.das` возвращает iterator из функции и использует его после её выхода.
  Ссылки/указатели не превращаются в глубокие копии: их время жизни обеспечивает вызывающий код.
- Внешние перемещаемые значения (например, `array<T>`) нельзя захватывать неявно:
  компилятор выдаёт `implicit capture by move requires unsafe`. Макрос не вставляет unsafe.
  Для явного владения снимком используйте deferred с аргументом данных
  ([DEFERRED_SEQUENCE.md](DEFERRED_SEQUENCE.md)); move-only источники описаны
  в [MOVE_COLLECTIONS.md](MOVE_COLLECTIONS.md).
- `use_resource` и `try_finally` поддержаны: см. `SEQUENCE_RESOURCES.md`.
  Native finally в CE по-прежнему запрещён; используйте явный try_finally.
- Вложенные обычные функции/блоки остаются обычным daScript; CE-маркеры
  предназначены для непосредственно преобразуемых областей computation.

Макрос раскрывает bind во вложенные нативные циклы внутри `generator<T>`.
Это отдельное преобразование AST: синхронные callbacks остальных builders
не сохраняются и не вызываются после окончания их стекового кадра.

## Yield в ListBuilder

Тот же синтаксис поддерживается для eager списков:

```das
var inscope values <- computation(ListBuilder()) {
    yield 1
    [2,3] |> yield_from
    yield 4
}
// [1,2,3,4], весь список построен до возврата computation
```

`return`/`return_from` остаются совместимы с предыдущей версией ListBuilder.
У Result/Option/State/Writer yield не добавлен.

Проверки: `run_computation.ps1 -Test`. Тестируются отсутствие работы до обхода,
ранний break без следующего шага, захват параметра после возврата функции,
два bind, bind без переменной, пустой bind, порядок yield_from, ветвления,
циклы, вложенные последовательности, строки и ожидаемые ошибки компиляции.


Локальные `var` внутри SequenceBuilder с ресурсными областями теперь разделяют
значение между телом, cleanup и продолжением. Пример: `sequence_shared_demo.das`;
срок жизни ячеек, стоимость и ограничения описаны в `SEQUENCE_RESOURCES.md`.

Вложенные iterator-источники `for`, `bind` и `yield_from` имеют отдельную
защиту закрытия: [SEQUENCE_NESTED_CLEANUP.md](SEQUENCE_NESTED_CLEANUP.md).
Пример: `sequence_nested_cleanup_demo.das`.
