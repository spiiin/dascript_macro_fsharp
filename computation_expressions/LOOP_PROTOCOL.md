# Переопределяемые For и While

`ce_for` и `ce_while` — необязательные операции общего протокола Value/Collect.
Новый builder определяет их в своём модуле; менять `computation.das` не нужно.

```das
require ./lib/computation_macro.das
require ./support/bounded_result_builder.das

var turns = 0
let result = computation(BoundedResultBuilder(limit=3)) {
    while (turns < 10) {
        variant<ok:bool;error:string>(ok=true) |> bind
        turns++
    }
    return turns
}
assert(result is error && turns == 3)
```

`bounded_result_builder.das` — рабочий пример внешнего builder. Лимит действует
на каждый цикл отдельно; For в этом примере принимает range; при превышении возвращается Error. Пустой цикл
успешен даже при нулевом лимите. Условия проверяются перед проверкой бюджета:
после последней разрешённой итерации условие может оказаться false и цикл
завершится успешно. Error из тела возвращается немедленно, без следующей
проверки условия. Отрицательный лимит работает как нулевой.

## Контракт

Условные сигнатуры (M — результат конкретного builder):

```text
ce_for(builder, source, body: block<(item:T):M>) : M
ce_while(builder, condition: block<():bool>, body: block<():M>) : M
```

- `source` вычисляется один раз при входе в For. Вывод типов не вызывает его.
- `condition` передаётся блоком: момент и число проверок определяет While.
- `body` — уже раскрытый CE-блок; каждый вызов применяет `ce_delay` к телу.
- Hook отвечает за обход, накопление эффектов и остановку. Для Result/Option
  результат каждой итерации — успешный CeUnit либо Error/None.
- Возвращаемое значение передаётся в обычный `ce_combine`. Поэтому Error/None
  пропускает также код **после** цикла. Терминальный цикл возвращает этот результат.
- Нельзя сохранять stack blocks для будущего вызова. Hooks синхронные; для
  сохранённого вычисления используйте `deferred`, которое создаст их при запуске.
- Collect hooks возвращают владеющий результат через `return <-`; они отвечают
  за удаление накопленных коллекций при native panic, как остальные Collect-операции.
- Временный массив-источник живёт до возврата hook и освобождается также при
  panic. Переменная-источник остаётся за владельцем. Элементы изменяемых массивов
  и изменяемых reference-итераторов передаются по ссылке.
- Iterator-источник передаётся для потребления. Hook обязан закрыть его, в том
  числе при ранней остановке. Result/Option используют явный курсор: закрытие
  выполняется при завершении, Error/None и исключении производителя или тела.
  Ссылочные элементы сохраняют возможность изменения исходных данных.
  Подробности и границы гарантии — [SINGLE_FOR_CLEANUP.md](SINGLE_FOR_CLEANUP.md).

Для общего For можно принимать `body:auto`: макрос уже задаёт тип аргумента
блока. Так одна перегрузка поддерживает и значения, и ссылки. При явном типе
блока сигнатура должна совпадать с типом элемента и его const/ref-квалификаторами.
Смотрите перегрузки Result/Option в `computation_builders.das`.

Тип аргумента For выводится через `typedecl(ce_for_element(source))`.
Это только вывод типа: функция не вызывается во время выполнения. Default
выводит элемент из native for, а массивы и итераторы имеют отдельные перегрузки.
Для собственного источника без native-итерации определите
`ce_for_element(source:MySource):MyElement` рядом с `ce_for` — пример есть в
`test_loop_dispatch.das`. Изменять макрос для нового источника не требуется.

## Совместимость и границы

Если подходящей перегрузки нет, marker `CeLoopFallback` выбирает прежнее
раскрытие через `ce_zero`, `ce_loop_append`/`ce_loop_failed` либо Collect append.
Marker никогда не вызывается во время выполнения. For и While можно добавлять
независимо. Hook, возвращающий void, отвергается с явной диагностикой.

`ce_for` используется для одного источника. For с несколькими источниками
поддерживает отдельный необязательный `ce_for_zip` с сохранением одновременного
перечисления; контракт и примеры описаны в [ZIP_FOR.md](ZIP_FOR.md).
Sequence использует отдельную генераторную стратегию и сохраняет native loops;
эти eager hooks не меняют её ленивость. Отложенный Value/Collect CE вызывает
hooks заново при каждом `run_deferred`.

## Проверки

`loop_protocol_demo.das` показывает ограниченный обход игровых целей и боевых
ходов. `test_loop_protocol.das` проверяет Error/None, вложенные циклы, пропуск
продолжений, число вычислений источника/условия, ссылки, владение временными
массивами, закрытие Sequence и повторный отложенный запуск.
`test_loop_dispatch.das` проверяет независимые hooks, отсутствие hooks,
zip и пользовательский Collect builder без legacy append-операций.
`test_computation_control.das` дополнительно покрывает пустые циклы, все позиции
ошибки в коротких циклах и 10 000 успешных итераций для Result и Option.

```powershell
./run_computation.ps1 -Test
```

Стандартный eager For без hooks также закрывает источники при исключениях:
[FALLBACK_CLEANUP.md](FALLBACK_CLEANUP.md). Пример: `fallback_cleanup_demo.das`.
