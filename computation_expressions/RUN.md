# Общий Run и граница вычисления

Необязательная операция `ce_run(builder, outcome)` преобразует внутренний
результат в публичный результат CE. Она вызывается один раз на внешней границе
каждого computation. Для Value/Collect это происходит после выполнения Delay
и освобождения ресурсов тела; для Sequence — после создания итератора.
Вложенный самостоятельный computation имеет собственную границу Run.
Обычные вложенные ветки и циклы не вызывают Run повторно.

```das
require ./lib/computation_macro.das
require ./support/report_builder.das

let report = computation(ReportBuilder(title="Reward")) {
    let p = result_ok(50) |> and_bind(result_ok(20)) |> bind
    let reward = p.first + p.second
    return reward
}
assert(report is completed)
assert((report as completed).value == 70)
```

В `report_builder.das` внутренние операции работают с Result, а Run выдаёт:

- `completed`: tuple с title и value;
- `failed`: tuple с title и message.

Это отдельный модуль без регистрации в computation.das. `run_demo.das`
показывает покупку предмета и передачу отчёта через границу функции.

## Контракт

```text
ce_run(builder, outcome: InternalResult) : PublicResult
```

PublicResult может отличаться от InternalResult. Поддержаны копируемые
результаты и результаты, передаваемые перемещением. Run должен возвращать
значение; void отклоняется с отдельным сообщением.

По умолчанию операция отсутствует: общий ce_run возвращает только типовой
маркер CeRunFallback. Макрос проверяет тип, не исполняя этот fallback,
и возвращает исходный результат. Существующим builders правки не нужны.
Не следует вызывать type-only fallback напрямую в пользовательском коде.

Value/Collect: сначала вычисляется внутренний результат через прежний Delay,
затем вызывается Run. Error, None и invalid — обычные результаты: Run получает
их тоже. Если тело или его cleanup бросает native panic, Run не вызывается.
Исключение самого Run находится за пределами try_with внутри тела CE; перехватить
его можно вокруг всего computation.

Sequence: сначала сохраняется прежний ce_sequence_run(builder, source), затем
его результат передаётся общему Run. Без общего Run последовательность остаётся
ленивой. Если пользовательский Run обходит итератор, он намеренно делает эту
операцию вычисления результата немедленной. Это проверено отдельным builder,
который сворачивает Sequence в сумму.

## Владение

Для Collect/Sequence макрос владеет внутренним результатом до окончания Run.
При обычном возврате или panic он освобождает этот результат. Run может читать
его или принять через var и переместить в собственный возвращаемый результат;
после перемещения исходный контейнер должен оставаться пустым и безопасным
для удаления. Нельзя сохранять ссылки/указатели на внутренний результат,
который макрос затем освободит.

Выходной перемещаемый результат принадлежит вызывающему коду: используйте
`var inscope result <- computation(...) { ... }`. За свои промежуточные
ресурсы внутри Run отвечает сама перегрузка, как и обычная функция daScript.

Это общий завершающий hook, а не реализация отложенных вычислений. Delay
Value/Collect по-прежнему синхронный; сохранять его stack block для последующего
запуска нельзя. Отложенное исполнение реализовано отдельно в deferred_computation
с владеющими снимками; см. [DEFERRED.md](DEFERRED.md).

## Диагностика

- Нет ce_protocol: ошибка указывает тип builder и допустимые дескрипторы.
- Неверный дескриптор: указаны builder, фактический тип и ожидаемые варианты.
- ce_run возвращает void: сообщение указывает, что требуется значение.

Проверки остальных операций по-прежнему используют диагностику перегрузок
и типов самого компилятора; этот пакет не заменяет её целиком.

## Память Collect

Дополнительно устранены утечки временных результатов yield/Combine и
источников одиночного bind с произвольным продолжением. Такие контейнеры
теперь живут в области владения макроса и освобождаются при успехе и исключении.
Заимствованные пользовательские контейнеры остаются у владельца.

## Проверки

- test_run.das: однократное создание builder, Run после cleanup, Error как
  значение, пропуск Run при panic, вложенные CE, отчёт с вложенным tuple,
  преобразование Value в массив, Collect в число/массив, Sequence в число,
  повторные исключения и закрытие ресурсов без роста heap.
- test_run_void.das: отрицательная проверка контракта.
- test_collect_temporaries.das: yield, циклы, ветки, временный источник bind
  и исключение после частичного результата без роста heap.
- Существующие отрицательные проверки ce_protocol дополнены более точной
  проверкой сообщения об отсутствующем протоколе.

Запуск: `./run_computation.ps1 -Test`; полная регрессия: `../run.ps1 -Test`.

## Отложенное выполнение

Отдельный модуль `deferred_computation` добавляет `deferred(builder, data) $(snapshot) { ... }` и `run_deferred(task)`. Снимки владеют данными, каждый
запуск получает независимую копию builder/data. Обычный computation остаётся
немедленным. Пример — `deferred_demo.das`; контракт и ограничения — [DEFERRED.md](DEFERRED.md).
