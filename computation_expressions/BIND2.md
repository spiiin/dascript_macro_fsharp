# Bind2: группа источников с произвольным продолжением

```das
let purchase = computation(ResultBuilder()) {
    let p = result_ok("Sword") |> and_bind(result_ok(50)) |> bind
    let cost = price(p.first) |> bind
    if (p.second < cost) {
        return result_error("Not enough gold", type<int>) |> return_from
    } else {
        return p.second - cost
    }
}
```

Полный запускаемый пример — `bind2_demo.das`. Пайповый синтаксис не изменён.
Теперь группа перед следующими bind, действиями, ветвлениями или return_from
может обходиться без промежуточного контейнера пары.

## Необязательная операция протокола

```text
ce_bind2(builder, left: M<A>, right: M<B>,
         next: block<(pair: tuple<first:A;second:B>): M<U>>) : M<U>
```

В отличие от Bind2Return, next возвращает готовое вычисление builder, а не
сырой результат. Сигнатура с одной парой соответствует синтаксису нашей
библиотеки. Операция должна быть эквивалентна MergeSources + Bind, включая
точный тип результата, порядок эффектов и ошибки.

Для соседнего обычного return порядок выбора: Bind2Return, затем Bind2,
затем прежний MergeSources + BindReturn/Bind. В остальных случаях: Bind2,
затем MergeSources + Bind. Обычные перегрузки стороннего модуля обнаруживаются
без регистрации в computation.das. Если операции нет, общий type-only fallback
CeBindReturnFallback оставляет старое раскрытие; он не вызывается в runtime.
ce_merge_sources и ce_unwrap по-прежнему нужны для вывода типа.

Оба источника вычисляются слева направо по одному разу, даже если первый
возвращает Error/None/invalid/пустой список. Native panic прерывает вычисление.
Result сохраняет первую ошибку; Option — None; Validation объединяет ошибки
в порядке источников. При неуспехе next не вызывается. Ошибки последующих
шагов подчиняются обычному Bind, а не накоплению независимых ошибок.
Bind без переменной также поддержан.

## List и вложенные группы

List делает поверхностные снимки обоих источников, затем вызывает next для
каждой пары (левый источник — внешний цикл) и добавляет элементы результата
next в общий массив. Промежуточного массива N*M пар нет: вспомогательная память
для снимков O(N+M), плюс результат и текущий результат продолжения. Массивы
продолжений по-прежнему создаются; их удаление не заменено потоковым выполнением.
Фиксированные/динамические источники и смешанные пары поддержаны.

Снимки сохраняют прежние значения при изменении исходных массивов внутри next.
Частичный результат, снимки и принадлежащие макросу временные источники
освобождаются при исключении. Пользовательские заимствованные массивы остаются
у владельца. Владением ресурсов внутри next управляют его CE-блоки.

Для трёх и более источников оптимизируется только внешнее объединение перед
bind. Внутренние MergeSources остаются на прежних местах: их порядок относительно
вычисления следующих источников может быть наблюдаемым. Формы вложенных пар
не изменились. Sequence этой оптимизацией не затронут.

## Проверки

- test_bind2_dispatch.das: прямой вызов операции, приоритет Bind2Return,
  builder только с Bind2, старый builder без оптимизаций, вложенные группы,
  порядок источников и bind без переменной.
- test_bind2.das: все комбинации успеха/неуспеха Result, Option и Validation,
  типы вложенных tuple, последующий отказ и native panic.
- test_bind2_list.das: порядок декартова произведения, несколько результатов
  на пару, пустой источник, все сочетания фиксированных/динамических массивов,
  мутация источников, cleanup и повторные исключения без роста heap.

В тесте 64×64 перед первым продолжением fast занимает 1024 байта heap,
контроль с явно материализованным MergeSources — 33280 байт. Это измерение
в одной точке, не оценка времени выполнения или пика памяти.

Запуск: `./run_computation.ps1 -Test` или полная регрессия `../run.ps1 -Test`.
