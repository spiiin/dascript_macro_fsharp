# ListBuilder: несколько результатов

`require computation` подключает ListBuilder. Выполнение синхронное, результат
материализуется целиком в динамический `array<T>`.

```das
var inscope values <- computation(ListBuilder()) {
    let x = [1, 2] |> bind
    let y = [10, 20] |> bind
    return x + y
}
// [11, 21, 12, 22]
```

`ListBuilder()` выбирает **int** как тип результата. Для другого типа укажите
его явно: `ListBuilder(type<string>)`, `ListBuilder(type<MyCopyableStruct>)`.
Это не вывод типа по return: явный тип нужен для Zero, пустых веток и циклов.
Типы источников bind могут отличаться от типа итоговых элементов.

## Bind и порядок выполнения

Bind вызывает продолжение для каждого элемента источника слева направо,
после чего соединяет все полученные списки в том же порядке. Источник —
фиксированный массив (`[1, 2]`) или динамический `array<U>`.

В примере выше первый источник вычисляется один раз; второй — два раза,
по одному для каждого x. После второго bind код выполняется четыре раза.
Дубликаты сохраняются, сортировки и устранения повторов нет.

Пустой источник не вызывает продолжение. Поэтому не выполняются последующие
вычисления и приобретения ресурсов в этой ветке. `ce_unwrap` используется
макросом только для вывода типа; обращение к source[0] не выполняется при bind
пустого источника.

Bind без переменной тоже поддержан:

```das
var calls = 0
var inscope values <- computation(ListBuilder()) {
    [1, 2, 3] |> bind
    calls++
}
// calls == 3; values пуст — блок не возвращал элементов.
```

Переменные до bind, изменяемые продолжениями, разделяются между их запусками;
ListBuilder не создаёт копии всего внешнего состояния и не делает rollback.
Переменная, объявленная через bind, создаётся заново для каждого элемента.
Не изменяйте заимствованный массив-источник во время его обхода.

## Return, Zero и Combine

- `return value` создаёт список из одного элемента.
- `return source |> return_from` копирует элементы готового фиксированного или
  динамического массива в новый результат. Источник не опустошается.
- Zero — пустой список заданного типа, не список с Unit.
- Combine соединяет результаты первой области с результатами продолжения.
  Продолжение выполняется один раз даже при пустом первом списке.

Последнее отличается от bind: пустой источник bind прекращает его продолжение,
а пустой результат промежуточного if не прекращает соседние инструкции.

```das
var inscope values <- computation(ListBuilder()) {
    if (true) { return 1 }
    if (false) { return 99 }
    return [2, 3] |> return_from
}
// [1, 2, 3]
```

По-прежнему нельзя писать инструкции после return в той же области.
Несколько результатов можно соединять через ветви/области, циклы и return_from.
Также доступны `yield value` и `source |> yield_from` (см. ниже).

## Ветки и циклы

```das
var inscope equipment <- computation(ListBuilder(type<string>)) {
    let weapon = ["sword", "bow"] |> bind
    let level = [1, 2, 3] |> bind
    if (weapon != "bow" || level >= 2) {
        return "{weapon}:level{level}"
    }
}
// sword:level1, sword:level2, sword:level3, bow:level2, bow:level3
```

Ветка без else возвращает пустой список и работает как фильтр.
For/while добавляют результаты каждой итерации. Пустая итерация не прерывает
цикл. В отличие от Result/State и других прежних builders, тело цикла и
промежуточная ветка здесь возвращают список элементов T, а не Unit.

```das
var inscope squares <- computation(ListBuilder()) {
    for (i in range(6)) {
        if (i % 2 == 0) { return i * i }
    }
}
// [0, 4, 16]
```

While заново проверяет условие перед итерацией; return внутри его тела
завершает результат итерации, не выходит из всего внешнего цикла. Для
завершения while нужно изменять его условие обычным способом.

## Владение результатом и ресурсы

Массивы daScript передаются через move:

```das
var inscope values <- computation(ListBuilder()) { return 42 }
```

Используйте `<-`, а не `=`, для получения результата computation.
`inscope` освобождает локальный массив на нормальном выходе из области.
Для копируемых элементов источники bind заимствуются, а результаты
return_from копируются. Move-only элементы поддержаны отдельной стратегией
`ListBuilder(type<T>)`: payload заимствуется через `var item & = source |> bind`,
а результат передаётся через `return <-` / `yield <-`. Подробнее:
[MOVE_COLLECTIONS.md](MOVE_COLLECTIONS.md). Материализация занимает память
пропорционально числу результатов; декартовы произведения могут быстро расти.

Using/TryFinally поддержаны специализированными перегрузками, передающими
массивы через move. Ресурс до первого bind открывается один раз и закрывается
после всех его продолжений; ресурс внутри продолжения открывается отдельно
для каждого достигнутого элемента. При panic дальнейшие элементы не
обрабатываются; очистка сохраняет правила [RESOURCES.md](RESOURCES.md).
Служебные накопители освобождаются при перехватываемом panic; пользовательские
внешние эффекты и заимствованные ресурсы не откатываются.

Это eager ListBuilder; для ленивого обхода добавлен SequenceBuilder (SEQUENCE.md). Асинхронное выполнение и отмена
этого builder не реализованы. Result/Option не поднимаются автоматически: их обработку
нужно явно определить до формирования источника списка.

## Реализация и проверки

`list_builder.das` содержит операции builder. Контекст — типизированная пара
с маркером ListContext и значением-заглушкой для типа выходного элемента.
Через ce_protocol выбирается стратегия CeCollectProtocol: макрос использует
move-возвраты и накопление элементов цикла. Пользовательский builder может
выбрать ту же стратегию; см. BUILDER_PROTOCOL.md.

```powershell
cd C:\src\dascript_macro_fsharp\computation_expressions
.\run_computation.ps1 -Test
```

`list_demo.das` показывает комбинации, подбор игрового снаряжения и фильтрацию.
`test_list.das` проверяет точный порядок, повторы, число вычислений источников,
пустые источники, разные типы элементов, оба вида return_from, сохранность
входных массивов, bind без переменной, Zero/Combine, for/while, вложенные CE,
10 000 итераций, ресурсы внутри/снаружи bind и очистку при panic.
Негативные тесты проверяют несовместимый источник, тип результата и явную
аннотацию переменной. Общий ../run.ps1 -Test включает все эти проверки.

## Обновление: yield

`yield value` добавляет элемент и позволяет продолжить текущий блок;
`source |> yield_from` добавляет все элементы источника. Прежние return
и return_from сохранены. Ленивый вариант — SequenceBuilder (`SEQUENCE.md`).


Оптимизация линейных List bind-цепочек и consuming-map, ограничения по
финализаторам, проверки и бенчмарки до/после: [LIST_OPTIMIZATION.md](LIST_OPTIMIZATION.md).
