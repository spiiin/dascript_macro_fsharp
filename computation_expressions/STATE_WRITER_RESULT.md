# StateWriterResultBuilder

Транзакционное состояние, журнал и Result. Подключается отдельным модулем:

```das
require ./lib/computation_macro.das
require ./lib/state_writer_result_builder.das

let outcome = computation(StateWriterResultBuilder(10)) {
    let current = state_get() |> bind
    state_put(current + 5) |> bind
    tell("added 5; ") |> bind
    return current
}
// outcome.result = Ok(10), outcome.state = 15, outcome.log = "added 5; "
```

Результат имеет поля `result:$Result<T;string>`, `state:S`, `log:string`.
Операции `state_get`, `state_put`, `tell`, `result_ok` и `result_error` используют
существующие типы библиотеки. Данные состояния и успешный результат должны быть
копируемыми. Выполнение обычного CE немедленное.

## Транзакция и журнал

- Начальное состояние builder — граница отката всего CE.
- При успехе результат содержит последнее состояние.
- Первый Error останавливает продолжение и восстанавливает начальное состояние.
- Журнал сохраняет записи до ошибки включительно, в порядке выполнения.
  Error сам по себе не добавляет сообщение в журнал; для этого используйте `tell`.
- Успешный дочерний StateWriterResult, переданный через bind, устанавливает своё
  состояние и добавляет свой журнал. Ошибка дочернего вычисления откатывает
  родительский CE к его начальному состоянию, сохраняя журналы обоих вычислений.
- Если после успешного дочернего вычисления произойдёт ошибка, его изменения
  состояния тоже откатываются, а записи журнала остаются.
- Простое вычисление дочернего результата без bind/return_from не меняет
  состояние родительского builder и не добавляет его журнал.

Для ручного создания результатов доступны:

```das
state_writer_result_ok(value, state, log)
state_writer_result_error(message, type<T>, state, log)
state_writer_result_value(result, state, log)
```

`log` можно опустить. При bind ошибки её поле `state` не принимается: используется
начальное состояние принимающего CE. `return source |> return_from` поддерживает
обычный Result, StateWriterResult и `tell(...)`.

## Циклы, ресурсы, отложенное выполнение

For, While и For с несколькими источниками используют стандартное раскрытие
общего протокола. Каждая итерация получает текущее состояние. Error останавливает
весь обход, откатывает состояние и сохраняет журнал выполненных итераций.

Ресурсные операции используют общие `use_resource`, `try_finally`, `try_with`.
Error не является исключением и не вызывает обработчик `try_with`.
Native panic не преобразуется в Error автоматически: если он выходит из CE,
результат с состоянием и журналом не возвращается. После перехвата panic внутри
CE продолжает действовать обычная семантика обработчика; автоматического отката
к началу CE только из-за panic нет.

`deferred(StateWriterResultBuilder(initial), data) $(snapshot) { ... }` сохраняет
вычисление. Каждый запуск начинается с собственного исходного состояния и
пустого журнала. Действуют ограничения снимков из `DEFERRED.md`.

## Границы

Откат касается только поля состояния. Внешние побочные эффекты и данные за
пользовательскими указателями не откатываются. Это копирование значений, а не
транзакция базы данных. Move-only состояние/результаты не поддерживаются.

`and_bind` здесь не реализован: операции изменения состояния следует связывать
последовательными bind. BindReturn использует общий fallback через Bind и Return.
Новые правила в `computation.das` или макросе не добавлены.

Пример с покупкой зелья и боем: `state_writer_result_demo.das` и
`game_logged_transaction.das`. Проверки: `test_state_writer_result.das`.
