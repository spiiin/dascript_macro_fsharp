# Защита вложенных источников Sequence

Iterator-источники в `for`, пайповом `bind` и `yield_from` теперь проходят через
`ce_sequence_input`. Это ленивый адаптер с собственным курсором: он закрывает
дочерний итератор при ошибке чтения и в своём финализаторе. Макрос применяет его
также к служебным итераторам ресурсных блоков и `try_with`.

Внешний Sequence уже имел защиту чтения и финализаторы native generator.
Теперь каждый вложенный iterator-источник имеет собственную точку закрытия.
Нативные массивы и диапазоны сохраняют прежний обход; дополнительные адаптеры
для них не создаются. Новых массивов результатов нет, но каждый защищаемый
iterator-источник добавляет один генератор-обёртку.

```das
return <- computation(SequenceBuilder()) {
    let enemy=enemies() |> bind
    yield enemy*2
}
```

`sequence_nested_cleanup_demo.das` показывает поток игровых наград: `break`
закрывает вложенный поток, а при его ошибке `try_with` выдаёт запасное значение
после освобождения ресурса.

## Гарантии

- Источник создаётся при достижении соответствующего шага, а не при создании CE.
- `yield` не закрывает источник: курсор живёт между запросами значений.
- Исчерпание, явный `sequence_close` и `break` из внешнего native for освобождают
  активные вложенные источники. Повторное закрытие не повторяет cleanup.
- Ошибка производителя или тела передаётся наружу; встроенная защита внешнего
  Sequence закрывает оставшиеся источники до выхода из неудачного `next`.
- Ошибка в коде внешнего потребителя требует `sequence_each` или явного
  `try/recover` с `sequence_close`: произвольный native for вне CE не изменён.
- Ссылочные итераторы сохраняют ссылки и изменения элементов; закрытие
  `each(array)` снимает блокировку. Value-итераторы требуют копируемых элементов.
- Источники ресурсного тела закрываются до его `ce_dispose`. При ошибке чтения
  первым закрывается ошибочный источник; остальные закрываются финализаторами
  внешнего генератора. Обратный порядок всей цепочки bind не гарантируется.
  Зависимое владение выражайте ресурсными областями.
- Для deferred каждый запуск имеет собственные итераторы; досрочное закрытие
  освобождает также удерживаемый снимок по прежнему контракту.

Финализаторы должны быть небросающими. Native runtime не гарантирует полное
освобождение памяти финализатора, который сам бросил исключение. Правила
захвата внешних ссылок и move-only данных остаются прежними.

`test_sequence_nested_cleanup.das` проверяет все три формы источников,
незапущенный и исчерпанный итератор, break и явное закрытие, ошибки до первого
и после нескольких yield, тело и внешний потребитель, создание следующего
zip-источника, вложенные bind, временные массивы, ссылочные элементы и повторные
deferred-запуски. Счётчики ресурсов и `heap_bytes_allocated()` проверяются
на повторных обходах. Общий запуск: `../run.ps1 -Test`.
