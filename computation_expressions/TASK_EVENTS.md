# Ожидание событий через Task

Подключение: `require ./lib/task_events.das` (Daslang 0.6.4, без нативных модулей).
Для синтаксиса CE также подключите `require ./lib/computation_macro.das`.
Источник событий удобен для UI, игровых сигналов и адаптации существующих
callbacks: callback вызывает `task_event_emit`, Task ожидает через пайповый bind.

```das
var actions:typedecl(task_event_source(type<string>))

def on_confirm_clicked() {task_event_emit(actions,"confirm")}

def confirmation_dialog() {
    return <- computation(TaskResultBuilder(type<string>)) {
        let action=task_wait_event(actions) |> bind
        return action=="confirm" ? "Purchase confirmed" : "Purchase declined"
    }
}
```

Инициализируйте `actions <- task_event_source(type<string>)` до запуска диалога.
В игровом цикле вызывайте `task_tick(scheduler,now_ms)`. Ожидание можно обернуть
в `task_with_cancellation(...,token)` и запустить с `TaskTimeout(after_ms=...)`.
Полный пример: [examples/task_events_demo.das](examples/task_events_demo.das).
Он имитирует нажатие между кадрами, закрытие UI с отменой и истечение таймаута.

## API и доставка

| Операция | Поведение |
|---|---|
| `task_event_source(type<T>)` | Новый move-only владелец источника |
| `task_wait_event(events)` | Холодный Task с Result<T>; подписка при первом poll |
| `task_event_emit(events,value)` | Передаёт значение всем уже подписанным ожиданиям; возвращает число получателей |
| `task_event_close(events)` | Закрывает источник; повторный вызов возвращает false |
| `task_event_subscriber_count(events)` | Число зарегистрированных ожиданий, включая уже получившие значение до их poll |
| `task_event_stats()` | Глобальные счётчики источников, Task-ожиданий и подписок для диагностики |

Каждое ожидание сохраняет только первое событие. Следующие события его значение
не заменяют. События до подписки теряются; истории, replay и очереди нет.
Новая Task, созданная после emit, ожидает следующее событие. Даже создание Task
до emit недостаточно: её первый poll должен зарегистрировать подписку.

Emit только копирует значения в слоты, не запускает пользовательские callbacks
или продолжения. Продолжение выполняется при следующем poll/tick. Для нескольких
ожиданий одного источника одно событие доставляется каждому из них. Это broadcast,
а не распределение сообщений между конкурентными потребителями. Разные источники
можно объединять через `and_bind`; проигравшие ожидания `task_race` закрываются
обычным протоколом Task. Отмена одного ожидания не закрывает источник и другие
подписки.

Строки копируются в собственное хранилище daScript даже при передаче заимствованного
`string#` из нативного callback. Исходный буфер можно изменить или освободить
сразу после emit; ожидающая Task получит сохранённый текст.

TaskResultBuilder распаковывает Result через bind. TaskBuilder получает сам Result
и позволяет обработать закрытие как данные. Ожидание поддерживает только
копируемые владеющие T: числа, строки, соответствующие структуры и кортежи.
Move-only значения, указатели, ссылки и исполняемые captures не поддержаны.

## Владение, закрытие и отмена

Подписка удаляется до запуска продолжения при успешном получении события, а также
при отмене, таймауте, удалении Task и закрытии планировщика. Зарегистрированный
слот и сохранённое значение освобождаются; новые emit его больше не видят.
Удаление Task до первого poll не создаёт подписку.

`var inscope events <- task_event_source(type<T>)` освобождает владельца при
выходе из обычной синхронной области. В CE источник можно создать локально через
`use_resource`. Источник move-only: его нельзя неявно скопировать в другую CE.
Для внешнего источника используйте стабильный UI bus, как в примере, либо
создайте `var wait <- task_wait_event(events)` до CE и переместите только эту
владеющую Task в вычисление. Такой захват move-only Task требует `unsafe` в
текущем синтаксисе daScript; вариант показан в `confirm` тестового файла.
Внешний владелец источника при этом остаётся у вызывающего кода.

Удаление владельца или `task_event_close` прекращают приём новых событий.
Уже созданные Task сохраняют внутренние данные до своего освобождения.
Ожидания без полученного события возвращают Error("task event source is closed")
при следующем poll. Уже сохранённое событие имеет приоритет над закрытием и
будет доставлено. Само закрытие не выполняет принудительный poll подписчиков.
Для немедленного освобождения ожиданий отмените их Task или закройте планировщик.

Отмена/таймаут дают Cancelled, а не Error. Доменный Error закрытого источника
даёт Succeeded с Result.error и пропускает продолжение TaskResultBuilder.
Исключение в продолжении даёт Failed; к этому моменту подписка уже удалена.

Источник, emit и Task работают в одном потоке. Для событий рабочего потока
сначала перенесите данные в поток игрового цикла: этот модуль не является
межпоточной очередью и не делает callbacks потокобезопасными.

## Проверки

[tests/test_task_events.das](tests/test_task_events.das): холодная подписка,
broadcast, сохранение первого события, повторная подписка, and_bind, независимая
и групповая отмена, таймаут по виртуальным часам, исключение в продолжении,
удаление источника до/после первого poll, перенос владельца, закрытие планировщика,
удаление Task и отсутствие роста heap после прогрева. Отдельные отрицательные
тесты запрещают указатели и move-only payload.
Отдельно проверяется копирование заимствованной строки с удалением её исходного
буфера до возобновления ожидающей Task.

Проверяются интерпретатор и JIT; AOT-исполнение этого адаптера пока не проверено.
