# Ограничение и объединение Search

`require ./lib/search_builder.das` предоставляет два потребляющих комбинатора:

| Вызов | Поведение |
|---|---|
| `source |> search_take(n)` | Первые `n` решений; `n <= 0` даёт пустой поиск без чтения источника |
| `left |> search_append(right)` | Все решения слева, затем все справа; повторы сохраняются |

Оба возвращают ленивый `iterator<T>` и работают вне CE и через `|> bind`:

```das
var inscope selected <- computation(SearchBuilder()) {
    let n=search_choose([1,2,3]) |> search_append(search_choose([10,20])) |> search_take(4) |> bind
    yield n*2
}
// 2, 4, 6, 20
sequence_each(selected) $(n:int) {print("{n}\n")}
```

Полный пример с ресурсами: [search_alternatives_demo.das](examples/search_alternatives_demo.das).

`search_take` читает не больше `n` элементов: дополнительного пробного чтения нет.
Источник закрывается **до выдачи n-го решения**. Даже если потребитель оставит
итератор приостановленным сразу после этого результата, ресурсы источника уже
освобождены. Если решений меньше, источник закрывается при обнаружении конца.
Неположительный лимит закрывает и уже начатый источник, не читая следующий элемент.

`search_append` сразу получает владение обоими iterator. Тело правого генератора
запускается только после исчерпания левого; левый закрывается до первого чтения
правого. Выражения, создающие iterator, вычисляются при вызове комбинатора;
ленивыми остаются тела генераторов. При закрытии объединения закрываются оба
источника, включая уже начатый правый. Захваченные массивы освобождаются даже у
не начатых источников; ленивые ресурсы, до которых выполнение не дошло, не приобретаются.

Объединение не удаляет дубликаты, не чередует источники и не откатывает эффекты.
Можно вкладывать `search_append` для трёх и более альтернатив. Бесконечный левый
источник не даёт перейти к правому. `search_take` ограничивает число решений,
а не время работы: ветвь, которая бесконечно ищет первое решение, он не прерывает.

Операции потребляют источники; повторный запуск требует новых iterator, например
через `run_deferred`. Элементы Search остаются копируемыми. Это не merge для Task
и не `and_bind`; альтернативы последовательно перебирают один тип решений.
`search_once`/`search_cut` сохраняют прежнюю семантику первого решения.

Владеющий результат сохраняйте как `var inscope`. Для обхода с возможным исключением
в потребителе используйте `sequence_each`: он закрывает поиск при `panic` из callback.
При ручных вызовах `ce_sequence_next_value` закрывайте источник сами, когда он больше
не нужен; `sequence_close` безопасен и после завершения/закрытия. В примере ранний
`break` дополнен явным `sequence_close`.

Исключение производителя прекращает объединение и закрывает оба источника;
правая альтернатива не используется как обработчик ошибки. Финализаторы ресурсов
должны быть без исключений, как и в общем [контракте CE](CE_SEMANTICS.md).

[test_search_combinators.das](tests/test_search_combinators.das) проверяет лимит,
нулевой/отрицательный лимит, пустые источники, порядок, дубликаты, вложенные
альтернативы, пайповый bind, scoped cut, закрытие до последней выдачи, break,
исключения производителя/потребителя, не начатые источники и стабильность heap
на 16 повторных запусках после прогрева. Набор включён в interpreter/JIT-проверки
и в список сборки и исполнения строгого AOT-хоста.

Проверено на SDK v0.6.5-RC2: interpreter и JIT без кеша выполнили
`test_search`, `test_search_combinators`, `test_domain_deferred` и новый пример.
Эти же четыре сценария собраны и выполнены отдельным C++ AOT-хостом с
`fail_on_no_aot` и проверкой `main->aot`; все четыре прошли. Остальные тесты
общего AOT-списка в рамках этого изменения повторно не запускались.
Экспорт библиотеки также проверен отдельным приложением с новыми операциями.
