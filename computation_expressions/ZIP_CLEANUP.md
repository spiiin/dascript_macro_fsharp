# Безопасное завершение zip при исключениях

Eager For с несколькими источниками, раскрытый через `ce_for_zip`, теперь
явно владеет курсорами. При `panic` в производителе или теле цикла:

1. Сохраняется исходное сообщение исключения.
2. Предпринимается закрытие каждого созданного курсора слева направо.
3. Освобождаются временные источники и снимаются блокировки массивов.
4. Исходное исключение передаётся наружу, в том числе в CE `try_with`.

Пример — `zip_cleanup_demo.das`: поток урона обрывается, ресурс закрывается,
обработчик восстанавливает выполнение, а массив целей снова можно расширять.
Синтаксис `for (a,b in first,second)` и пайповый bind не изменились.

## Сохранённая семантика

Обход до конца самого короткого источника остаётся одновременным.
Первый проход пытается получить начальный элемент всех источников, даже если
один пуст; последующие проходы прекращают чтения на первом завершившемся
источнике. Это проверяется сравнением с native for. Если чтение бросило
исключение, остальные чтения этой итерации не выполняются.

Элементы изменяемых массивов и reference-итераторов сохраняют ссылки.
Readonly-источники остаются readonly. Cursor хранит значение для value-итератора
и адрес элемента для reference-итератора; промежуточные массивы пар не создаются.
Внутренние ссылки на текущие элементы действительны только в синхронном теле.

Поведение Error/None и `ce_for_zip(builder,arity,traverse)` не изменилось.
Исключение автоматически не превращается в Error/None: используйте `try_with`
или native `try/recover`, когда требуется восстановление.

## Границы

Защищён путь **через `ce_for_zip`**: Result/Option, BoundedResultBuilder и
пользовательские перегрузки. Builder без этой операции использует
[защищённый fallback](FALLBACK_CLEANUP.md). Для одиночного For Result/Option действует аналогичное
закрытие: [SINGLE_FOR_CLEANUP.md](SINGLE_FOR_CLEANUP.md). Генераторная
стратегия Sequence использует отдельное раскрытие.

Финализаторы должны завершаться без исключений, как и прежде. Если финализатор
сам бросает ошибку, runtime всё равно пытается закрыть остальные курсоры и
сохраняет исходную ошибку производителя/потребителя; без исходной ошибки
пробрасывается первая ошибка закрытия. Освобождение внутренней памяти
финализатора, прерванного panic, ограничено поведением native runtime daScript.

## Проверки

`test_zip_exceptions.das` повторяет ошибки каждого из трёх производителей до
первого yield и после нескольких yield, ошибки потребителя, освобождение
временных массивов, ошибку создания следующего источника и повторные запуски
`deferred`. Проверяются счётчики открытых/закрытых ресурсов, исходное сообщение,
пропуск продолжения и возврат heap к исходному размеру. `try_with` видит ошибку
только после закрытия источников.

`test_zip_readonly.das` проверяет запрет изменения readonly-элемента,
а `test_zip_cursor_values.das` — смешанный обход структур-значений, строк
и изменяемых элементов массива.
Существующие `test_zip_for.das` и `test_zip_dispatch.das` проверяют порядок,
короткий источник, ссылки, Error/None и пользовательские builders.

Запуск: `../run.ps1 -Test`.
