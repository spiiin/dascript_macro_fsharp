# For с несколькими источниками

```das
require ./lib/computation.das

var inscope health <- [100,200,300]
let damage = fixed_array(10,20)
let result = computation(ResultBuilder()) {
    for (hp,hit in health,damage) {
        let amount = variant<ok:int;error:string>(ok=hit) |> bind
        hp -= amount
    }
    return health[0]
}
assert(result is ok && result as ok == 90)
assert(health[1] == 180 && health[2] == 300)
```

Источники обходятся одновременно, как в native `for`, до конца самого короткого.
Это zip, не декартово произведение. Количество источников не фиксировано:
поддерживаются два, три, четыре и больше. Типы источников и элементов могут
различаться; элементы изменяемых массивов сохраняют ссылки. Источники должны
поддерживать native for; helper одиночного For `ce_for_element` здесь не применяется.

Для Result/Option Error/None из тела немедленно останавливает весь цикл.
Следующего чтения ни одного источника нет, все открытые итераторы закрываются,
код после цикла пропускается. Успешный пустой цикл возвращает Zero.
Пайповые `let x = operation |> bind` и `operation |> bind` работают как прежде.

## Протокол

Новая необязательная операция:

```text
ce_for_zip(builder, arity:int,
    traverse:block<(visit:block<(body:block<():M>):bool>):void>) : M
```

`M` — тип `ce_zero(builder)`, например Result<CeUnit>, Option<CeUnit> или
массив Collect. Макрос не знает конкретных имён builders.

`arity` сообщает число источников. `traverse` — синхронный обход всех источников;
на каждой полученной группе элементов он вызывает `visit`, передавая блок тела
этой итерации. Возврат `false` из visit останавливает обход и закрывает итераторы.
Сам body уже содержит раскрытый CE и применяет `ce_delay` при вызове.

Пример реализации для Result:

```das
def ce_for_zip(builder:MyBuilder; arity:int;
    traverse:block<(visit:block<(body:block<():variant<ok:CeUnit;error:string>>):bool>):void>) {
    var result = ce_zero(builder)
    invoke(traverse, $(body:block<():variant<ok:CeUnit;error:string>>) {
        result = invoke(body)
        return result is ok
    })
    return result
}
```

Результат hook поступает в обычный `ce_combine`. Для Collect возвращайте
владеющий результат через `return <-` и освобождайте накопленные данные
при исключениях, как в других Collect-операциях.

Вызовите traverse один раз для исполнения цикла или не вызывайте его, если
политика builder запрещает запуск. Источники вычисляются **при вызове traverse**,
слева направо, по одному разу — в том числе если один из них пуст. До этого
макрос только выводит типы, не исполняя выражения. Сохранять traverse/visit/body
нельзя: это stack blocks. `deferred` поддерживается на уровне всего CE и создаёт
новый обход при каждом запуске.

Такой контракт сохраняет ссылки на элементы и неоднородные элементы без упаковки
в кортежи и материализации промежуточного массива пар. Единственная zip-операция
builder обслуживает любое количество источников. Одиночный `ce_for` сохраняет
свою сигнатуру и вызывается независимо от `ce_for_zip`.

## Владение и совместимость

Макрос удерживает каждый временный массив в отдельной области до закрытия
всех итераторов. Массивы-переменные заимствуются, а iterator-источники потребляются
как в native for. Освобождение временных массивов проверяется по размеру heap
для раннего Error и None. Native блокировка массивов сохраняется; после остановки
массив снова можно расширять.

Если `ce_for_zip` не определён, остаётся прежнее раскрытие через loop/collect
append. Старые одиночные `ce_for`, включая generic-перегрузки, не перехватывают
новый вызов. Sequence сохраняет собственную генераторную стратегию.

Error/None — обычные значения. Путь через `ce_for_zip` также закрывает курсоры
при native panic производителя или потребителя: [ZIP_CLEANUP.md](ZIP_CLEANUP.md).
Исходное исключение сохраняется для внешнего `try/recover` или CE `try_with`.
Fallback без hook сохраняет прежнюю реализацию.

## Примеры и проверки

- `zip_for_demo.das`: урон по целям и обход трёх источников с лимитом итераций.
- `bounded_result_builder.das`: внешняя перегрузка zip без изменения фасада
  или макроса; единица бюджета — одно выполненное тело, а не отдельный источник.
  Для обнаружения превышения лимита следующая группа элементов уже получена,
  но её тело не вызывается.
- `test_zip_for.das`: разные длины, пустой источник в каждой позиции, все позиции
  ошибки, два/три/четыре источника, вложенность, ссылки, порядок вычисления,
  память временных массивов, закрытие трёх Sequence и повторный deferred-запуск.
  При нормальном завершении timing `next()` сравнивается с native for: очередное
  чтение некоторых источников для обнаружения конца самого короткого допустимо.
- `test_zip_dispatch.das`: пользовательские Value/Collect hooks, arity, запрет
  запуска без вычисления источников и совместимый fallback для List.
- `test_zip_void.das`: диагностика hook, возвращающего void вместо результата.

Запуск: `./run_computation.ps1 -Test` либо полный `../run.ps1 -Test`.
