# Безопасное закрытие одиночного For

Встроенные `ResultBuilder` и `OptionBuilder` явно владеют iterator-источником
одиночного `For`. Пайповый bind и сигнатура `ce_for(builder, source, body)`
не изменились. Дополнительной обёртки в пользовательском коде не требуется.

```das
let outcome=computation(ResultBuilder()) {
    try_with($ {
        for (damage in damage_feed()) {
            let amount=result_ok(damage) |> bind
            health-=amount
        }
        return 0
    }, $(message:string) {
        assert(closed==1)
        return -1
    })
}
```

Полный игровой пример — `single_cleanup_demo.das`: источник урона выдаёт
два значения и бросает исключение; обработчик запускается после освобождения
ресурса источника. Уже применённый урон сохраняется — автоматического отката нет.

## Время жизни

- Итератор потребляется, закрывается при исчерпании, Error/None и исключении.
  После Error/None следующий элемент не запрашивается.
- Используется тот же курсор, что в zip: значения хранятся в типизированном слоте,
  reference-итераторы сохраняют ссылки. Закрытие `each(array)` снимает блокировку.
- Перед cleanup сохраняется исходное сообщение исключения; после закрытия оно
  пробрасывается дальше. Источник отсоединяется до вызова его финализатора,
  поэтому повторное закрытие потреблённой переменной безопасно.
- Обычные массивы продолжают использовать индексный обход с защищённой
  блокировкой; временные массивы удаляются также при исключении.
- Сохранённые вычисления используют этот же путь при каждом запуске.

## Границы

Гарантия относится к встроенным `ce_for` Result/Option. Пользовательский hook
отвечает за закрытие сам. Стандартный eager fallback других builders также
защищён: [FALLBACK_CLEANUP.md](FALLBACK_CLEANUP.md). Sequence использует отдельное
генераторное раскрытие. Для value-итераторов элементы должны быть
копируемыми, как в существующем zip-курсоре. Финализаторы ресурсов должны быть
небросающими: native runtime не гарантирует освобождение собственной памяти
финализатора, прерванного новым исключением. Ошибки внутри самого конструктора
источника до передачи владения остаются ответственностью конструктора.

`test_single_exceptions.das` проверяет исключения до первого yield и после
нескольких элементов, ошибки тела, исходное сообщение в try_with, освобождение
ресурсов, блокировки reference-итератора, повторное закрытие, временные массивы,
крупные значения и повторные deferred-запуски. Проверки памяти сравнивают
`heap_bytes_allocated()` до и после; тесты повторяются пять раз. Нормальный выход,
Error/None и отсутствие лишнего чтения также покрыты `test_loop_protocol.das`.
