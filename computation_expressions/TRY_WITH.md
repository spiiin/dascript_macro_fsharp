# TryWith: обработка исключений в CE

Подключение прежнее: `require computation`. Поддержаны Result, Option, State,
Writer, WriterResult, StateResult, List и Sequence builders.

```das
let result = computation(ResultBuilder()) {
    try_with($ {
        return load_value()
    }, $(message : string) {
        print("recovered: {message}\n")
        return 42
    })
}
```

`try_with` — отдельная инструкция CE. Первый блок без аргументов содержит
вычисление, второй получает строку сообщения native исключения. Оба блока
понимают bind через пайпы, return/return_from, ветвления и циклы, согласно
правилам builder. Тип результата тела и обработчика должен совпадать.
Если после try_with есть инструкции, действуют обычные правила Combine:
у скалярных builders промежуточная область возвращает Unit; у List/Sequence
допускается выдача элементов.

Обработчик вызывается только при перехватываемом исключении daScript
(panic, неудачный assert и аналогичные runtime ошибки). Error/None — значения,
поэтому сами по себе не вызывают обработчик. Ошибка компиляции не перехватывается.
Ошибка внутри обработчика не обрабатывается им повторно: она выходит наружу,
где её может поймать другой try_with.

## Ресурсы и эффекты

use_resource и try_finally внутри защищённого тела завершают очистку до входа
в обработчик. Ошибка cleanup заменяет исходную ошибку, внешние cleanup также
выполняются. Ресурс, открытый снаружи try_with, остаётся открыт на время и тела,
и обработки. Обычные внешние эффекты (печать, изменение объектов, I/O) не откатываются.

State сохраняет изменения, выполненные до исключения. Для StateResult исключение
само по себе также не означает откат: обработчик может вернуть Error через
return_from, и тогда сработает существующий откат StateResultBuilder. Writer
и WriterResult не восстанавливают журнал не завершившегося значения; журнал
обработчика строится заново. Eager List возвращает список обработчика, без
частично накопленного списка упавшего тела.

## Ленивое восстановление

```das
var inscope values <- computation(SequenceBuilder()) {
    var n = 1
    try_with($ {
        yield n
        n = 2
        panic("source failed")
    }, $(message : string) {
        yield n + 10
        yield n + 20
    })
    yield n + 30
}
// При полном обходе: 1, 12, 22, 32
```

SequenceBuilder сохраняет ранее выданные элементы. При ошибке он закрывает
исходный iterator, один раз создаёт последовательность обработчика и продолжает
обход с неё. Исходное тело не перезапускается. Пустой обработчик позволяет
перейти к следующим инструкциям. Локальные var внутри CE разделяются между
телом, обработчиком и продолжением по правилам `SEQUENCE_RESOURCES.md`.

До первого запроса ничего не выполняется. Break до ошибки не вызывает обработчик;
break внутри обработчика закрывает его ресурсы и не выполняет оставшиеся шаги.
Ошибка cleanup при естественном окончании защищённого тела может вызвать
обработчик. При закрытии из-за break последовательность уже прекращает работу:
ошибка cleanup передаётся наружу, обработчик не запускается для выдачи новых элементов.

Ошибка потребителя находится за пределами CE и не попадает в этот try_with.
Для потребителя, который может бросить исключение, используйте sequence_each:
он гарантирует закрытие iterator, как описано в `SEQUENCE_RESOURCES.md`.

Native try/recover не охватывает yield. Перехват находится вокруг next;
обработчик и его iterator принадлежат текущей области и освобождаются при закрытии.
Это сохраняет работоспособность на runtime 0.6.4. Сохраняется сообщение ошибки,
но при повторном panic исходный стек/место исключения не гарантируются.

Пример: `try_with_demo.das`. Тесты охватывают все builders, обход без ошибки,
Error/None, очистку до обработчика, вложенное восстановление, ошибку обработчика,
break, пустой handler, циклы, типовые ошибки и возврат памяти к исходному объёму
после 100 восстановлений. Запуск: `run_computation.ps1 -Test` или `../run.ps1 -Test`.
